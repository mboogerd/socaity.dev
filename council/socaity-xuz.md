# Council: socaity-xuz — Ledger presentation when the founder is nearly the only contributor

Participants: product-designer, launch-strategist, mechanism-designer
Type: research · Priority: P0

Issue:
- Context: at M0 the ledger shows ~100% founder share of epoch 0 and early epoch 1. To the OSS-sustainability cohort this can pattern-match a crypto pre-mine; to skeptics it reads as self-dealing. The ledger page is also the recruiting surface ("claim the first external entry").
- Question: How is the ledger presented so that a founder-dominated record reads as honest bookkeeping rather than a pre-mine — display design, framing copy, and any mechanism-side devices?
- Why it matters: The glass house's first exhibit is the founder's own pay. If it reads wrong, the M0 cohort bounces.

Adopted context binding this council (substantial machinery now exists — build the presentation on it):
- socaity-19p: flat 1h=1vu rate card (one screen); founder rate ≤ grant-funder referent at median, pinned in V; non-beneficiary attestation gate; concentration tripwire dashboard ("founder share: 100% because N=1; here is the curve"); founder entries challengeable at lower friction; itemized epoch-0 founder position (individual per-contribution observations, same evidence standard).
- socaity-1ux: two-register Standing Commitment; canonical paragraph; vocabulary standard (no currency formatting, no balances-as-holdings; epoch shares as fractions/percentages of closed epochs); "no token, nothing to trade, the ledger is a database" first-screen assets.
- socaity-x8o: epoch weights are scale-invariant fractions; payout amounts exist only upon declaration; mode-E displays as percentages.
- socaity-ipg: unclaimed-escrow state designed ("attribution reserved"); ledger permalink is the product; quiet archival aesthetic; OG cards.
- socaity-zjr/7mk: provisional/confirmed statuses; challenge affordances; pseudonymous keys + display names.
- Remaining scope: the ledger page's actual information design (what a stranger sees in 30 seconds, per the PD charter), the founder-share framing copy and its honesty rails, the contribution-worth calculator's place (socaity-m3i), and any additional device the roles deem necessary for the pre-mine pattern-match problem specifically.

## Round 1

### [product-designer]
PROPOSAL (owner). Design thesis: every element renders something already adopted — the page's honesty is load-bearing because nothing on it is presentation-only.
**A. Strict vertical order = the 30-second read:** Screen 1 "What is this + who contributed what" — 1ux register header ("A public record of contributions. No token. Nothing to trade. This is a database."); the contribution table (recent first: name/truncated key, plain-words event type, category, vu, status chip, evidence link, permalink; unclaimed escrows in the ipg reserved state). The table IS the page. Screen 2 "What rule converts contribution to claim" — the V rate card rendered whole as a card (19p designed it to fit one screen), plus three inline affordances: "recompute this yourself" (export + script), the attestation statement, the canonical paragraph → operative text. Every number on screen 1 re-derivable from screen 2 — adjacency is the trust argument. Screen 3 "What would MY contribution be worth" — the m3i calculator: input category + hours or tier; output vu and % of current epoch against closed-epoch percentages as the only referent; never currency, never payout projections; runs the literal published V code and says so.
**B. Founder-share rendering:** the pre-mine read comes from three visual cues — big number styled as balance, unexplained concentration, unchallengeable record. So: **concentration panel as dashboard, not disclosure** ("Founder share of epoch N: 100% — because contributors: 1" — denominator is the headline), with the curve-as-others-join (one real point + the mechanical dilution band implied by the rule, interval-styled, "what this number does when you show up"), plus the public tripwire state ("above X%, entries auto-escalate — currently: escalated"). **Itemization kills the lump:** founder position never one row; epoch-0 renders as individual observations, boringly identical to external rows — a pre-mine is a block grant; a worklog is a job; the visual identity of founder rows and external rows IS the argument. **Challenge affordances visible on every founder row** ("flag this entry", founder-answers-publicly threads under the row) — an unchallenged record with no visible path reads unchallengeable. **Vocabulary rail CI-enforced:** percentages of closed epochs only; no currency, balance, holdings, wallet; founder rate shown "≤ [referent] at median, source pinned".
**C. Genesis timeline** (quiet, vertical): each step links its on-chain event; copy notes "the validator refuses external entries before this sequence completes" — turning "the founder went first" from optics into protocol; **the terminal node is visibly empty and claimable** — the timeline ends in the recruiting surface.
**D. Aesthetic:** archival-editorial; public registry one could cite, not a dashboard one could trade on; no animated numbers ever (counting-up totals are a crypto tell).
**E. Exactly two CTAs, both diegetic:** the empty terminal timeline node ("This entry is unwritten. Claim the first external entry →") and the calculator output line. No banner, no modal, no third.
**Tests:** stranger answers the three questions in ≤30s; reads the 100% panel and states WHY ("he's the only one so far") not WHAT ("he kept it all") — the pass/fail line; states "the catch" without saying token/airdrop/scheme.
**PARAMOUNT:** no currency figure anywhere on /ledger; no aggregate founder lump-sum row; **no de-emphasis of the founder share** (no burying, footnoting, scale tricks, chart truncation — honesty rails run both directions); no urgency/scarcity CTA mechanics; no ship without the comprehension test passing (if strangers read "kept it all", we redesign the panel, not add copy on top).
Handoffs: LS — screen-1 header copy + OG framing; MD — confirm the dilution band derives purely from the published rule with no promissory surface, and that "% of current epoch" respects x8o display rules while the epoch is open.

### [launch-strategist]
**1. Headline framing: state the worst thing first, in declarative bookkeeping voice, before any chart.** Canonical block under the page title: *"Founder share of epoch 0: 100%. Of epoch 1 so far: 100%. There is one contributor. That contributor is the founder, and this ledger is his own pay, itemized. Every entry below is an individual observation with evidence, priced at the same flat rate that applies to anyone. The founder's rate is pinned at or below the grant-funder median referent. Nothing here is a currency, a balance, or a stake — epoch shares are fractions of closed epochs, and payout amounts exist only if money is ever declared against an epoch."* Every clause a link, not a claim. Register: quiet audit report — no "we believe in radical transparency" throat-clearing; the page never says the word "transparent". **Structural rail: the 100% is rendered live from ledger data, never hand-written** — stale honesty reads as abandoned honesty; a computed number that visibly falls when entry two lands turns the embarrassing stat into an instrument.
**2. The screenshot test:** assume the hostile crop (title + "100%" + founder pay rows, all context links lost). The headline block is self-indicting AND self-explaining in one breath — a screenshot of it is a screenshot of us saying it first; **the worst screenshot of this page should be the same screenshot we would post ourselves** (literal test: crop at 1200×630, caption "lol pre-mine", check the crop answers the caption). Per-row anti-crop hygiene: evidence link, hours × rate, status INSIDE each row. The OG card is the disclosure authored by us: "Epoch 0 — 1 contributor (founder) — 100% — all entries itemized & challengeable." No summed founder total styled as a balance anywhere — a cropped total is the pre-mine screenshot.
**3. Pre-mine answer resident ON the page** (collapsible "Is this a pre-mine?" under the headline — name the objection in its own words; euphemism is spin): (1) nothing is tradable, nothing to buy into; (2) nothing was allocated — everything worked and logged at a flat public rate with evidence ("a pre-mine is a grant; this is a timesheet"); (3) founder entries are the EASIEST to attack, not the hardest (lower threshold, attestation gate, challenge link on every row). **Plus the load-bearing concession: "What this page can't prove yet: that the mechanism works with more than one participant. That's an open problem, and it's the point of the next line on this page."** Never overclaim — the message is "legible, priced, challengeable, expected to fall — and here's what it doesn't prove."
**4. "Be entry two" as the resolution of the objection, not a promo unit:** "Entry two doesn't exist yet. The concentration number above stays 100% until someone else does priced, evidenced work. Same rate card, same evidence bar, same challenge exposure as the founder's rows." Sits directly under the pre-mine answer; the ipg reserved-escrow state shows the empty second slot as a real ledger row — the recruiting surface is a fact about the ledger (a visible absence), not a marketing module. First act of the invitation = the calculator = full price disclosure ("an invitation whose first move is full price disclosure cannot be a growth hack"). Crop test applies: "Entry two doesn't exist yet" cropped alone is self-deprecating recruiting.
**PARAMOUNT:** no hedging/burying/euphemizing the 100% (if it isn't the first thing a stranger reads, I object at consent); no scarcity/status mechanics on the entry-two CTA (numbered badges, countdowns, "limited"); no currency/holdings visual grammar; **no M0 launch before the pre-mine answer is resident and the page passes the crop test with a real screenshot.**

### [mechanism-designer]
**No additional mechanism-side device — one boundary item, then presentation.** (1) The pre-mine test stated economically is already closed: allocation-precedes-rule (blocked: rate published before accrual, referent-pinned); insider-units-at-zero-cost (blocked: attested labor, re-derivable from artifact + V); rule-drift-favoring-insiders (blocked: prospective-only + comment + attestation re-check). **And the deepest fact: epoch shares are per-epoch pools — founder dominance of epoch 0 taxes no later entrant; epoch 0's 100% is arithmetically incapable of touching epoch 5's pool.** The single most persuasive non-pre-mine fact we own, pure existing mechanism; making "your epoch starts at zero founder share" legible in 30 seconds is the remaining design scope. Adding machinery would signal we don't believe our own arithmetic. (2) **Pre-seeded self-challenge: reject as theater and worse** — founder as flagger, respondent, and (at N=1) effective adjudicator is a simulated adversarial transaction: the wash-trading signature the crypto-literate cohort is primed to detect; detection converts "maybe pre-mine" into "definitely performing." Nothing structural can honestly manufacture adversarial history at N=1; when the founder finds his own bookkeeping error (he will), it must run through the public challenge machinery rather than silent amendment — that yields the real first challenge record. Operating discipline, not a device. (3) **Boundary item: re-derivation ships as runnable code** — V executable + open recompute script, per-entry "recompute this" affordances, per-entry challenge-window state ("open until X · 0 challenges"). The implication of "pinned in V's code" discharged as code, not prose.
**PARAMOUNT:** no staged/pre-seeded challenges ever; no optics-driven retroactive treatment of epoch 0 (haircut, special vesting, "voluntary" targets — any rule about WHO breaks the uniformity covenant, and bending rules to criticism is itself the strongest pre-mine signal); no copy quantifying founder share against a "target" or "cap" (resurrects the rejected cap as insinuation); standing vocabulary constraints hold. CONSENT conditional on refusal (i) binding the presentation work: no exhibit may simulate adversarial or third-party activity that did not occur.

## Resolution

ADOPTED by consent, Round 3, no paramount objections standing.

**The /ledger presentation (M0):**
1. **Screen 1:** register line ("A public record of contributions. No token. Nothing to trade. This is a database.") + the canonical headline block stating the worst fact first in bookkeeping voice ("Founder share of epoch 0: 100% … one contributor … his own pay, itemized"), set as body prose, every clause a link, percentages live-rendered from ledger data, never hand-written. Collapsible "Is this a pre-mine?" directly beneath: (1) nothing tradable; (2) nothing allocated — worked and logged ("a pre-mine is a grant; this is a timesheet"); (3) founder entries the easiest to attack (lower threshold, attestation, per-row flag); (4) **per-epoch pools: epoch 0's 100% arithmetically cannot touch any epoch you contribute to — your epoch starts at 0% founder share**; closing concession LAST: "what this page can't prove yet: that the mechanism works with more than one participant — that's the point of the next line."
2. **Contribution table as the page:** per-row: name/truncated key, plain-words type, category, vu, status chip, evidence link, hours × rate INSIDE the row (anti-crop), "recompute this" (runs the published V code), challenge-window chip ("open until X · N challenges"), permalink; founder rows boringly identical to external rows; epoch-0 itemized, never a lump; unclaimed escrows in the ipg reserved state.
3. **Concentration panel:** live share + "because contributors: 1" (denominator is the headline) + real tripwire number and state + the **"Your epoch" pool exhibit** ("Epoch N+1 founder share: 0% until he logs work in it, same as you — epochs are separate pools"). No dilution curve (deleted: caption-dependent honesty fails the crop test).
4. **Rule card (screen 2):** the one-screen V card rendered whole; attestation statement resident; canonical paragraph → operative text; every screen-1 number re-derivable from screen 2.
5. **Calculator (screen 3, m3i):** input category+hours/tier; output vu unqualified (final at entry) + "if the epoch closed today: Y% — an upper bound; it can only fall as more work is logged"; open-epoch figures never in series with closed epochs; runs the literal published rule code and says so; output line doubles as CTA #2.
6. **Genesis timeline** ending in the visibly empty, claimable first-external-entry node (CTA #1); "Entry two doesn't exist yet" recruiting copy as the resolution of the pre-mine objection, never a promo unit; exactly two CTAs, both diegetic.
7. **Rails:** no currency grammar anywhere; no lump-sum founder row; no de-emphasis of the 100% (honesty runs both directions); no urgency/scarcity mechanics; no simulated activity ever (founder self-corrections run through the public challenge machinery — the real first challenge record); no animated numbers; archival-editorial register; OG cards authored as the disclosure ("Epoch 0 — 1 contributor (founder) — 100% — itemized & challengeable").
8. **Ship gates:** 5-stranger comprehension test (reads "100% because N=1" as WHY not "kept it all"; if it fails, redesign the panel, don't add copy); LS's real-screenshot 1200×630 crop test on the headline block, the panel, and the "0%" pool exhibit; pre-mine answer resident before any launch.

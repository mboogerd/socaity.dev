# Council: socaity-0hb — M0 visual design system: what socaity.dev should look like

Participants: product-designer (owner), launch-strategist, platform-engineer, community-builder

Issue:

- **Context.** The site is functionally complete (home/manifesto, `/faq`,
  `/ledger`, `/claim`, `/roadmap`, node pages, `/blog`) but visually unstyled
  beyond the minimal CSS the toolchain shipped.
  `doc/standards/vocabulary-and-visual.md` fixes the constraints as pass/fail
  checks (V1–V14: editorial document register, no glassmorphism / neon / coin
  iconography / countdowns, every number links to its derivation, no
  colour-only signalling, WCAG AA) — but a checklist of refusals is not a
  design.
- **Question.** What is the positive visual language — typography, scale,
  colour, spacing, layout, the treatment of chips / tables / provenance /
  numbers, the 1200×630 crop, dark mode — that makes a stranger read this as a
  serious editorial document about public infrastructure rather than a product
  launch or a token site?
- **Why it matters.** The anti-crypto signal is visual before it is verbal
  (socaity-uun); the manifesto's first screen is where the pattern-match is won
  or lost (socaity-im1); and the five-user comprehension test (socaity-mqk)
  blocks launch on exactly this reading. Decisions taken now harden into the
  templates every future surface inherits.
- **Output shape.** A specification implementable as CSS plus template changes
  — not mood boards.

Constraint inputs: `doc/standards/vocabulary-and-visual.md` V1–V14;
`council/socaity-xuz.md` (ledger presentation rails); `council/socaity-z61.md`
and `socaity-sbb.md` (status chips, focus+context); the existing
`tools/render/templates/` and `tools/render/style.css`.

## Round 1

### [product-designer]

Built and read the site at 1280 and 375 first. What exists is not unstyled — 61 lines carrying real decisions (Georgia body, one column, chips that survive greyscale by border-style, a real 1200×630 card for blog posts). It is honest and inert. Named failures from the rendered pages: no first screen exists (the largest object above the fold is a caveat about publication logistics; the thesis sentence is ~700px down at body size); the column is 704px inside 1280 with 288px of dead margin per side, so all metadata is jammed into the reading flow as grey caption soup; ledger entries are two `<tr>`s that don't look related and `confirmed` renders twice per entry; the concentration figure is set at 1.9rem in **system-ui** while the page is Georgia — the one number that must read as bookkeeping is the one object in the dashboard font; the legend renders in full on every page and on a leaf node is physically larger than the node; no dark mode at all; no OG card except blog; every template carries its own `<style>` block (`ledger.html` alone redefines 24 rules).

**PROPOSAL.**

**1. Type.** Three roles, two loaded faces, one webfont. `--font-text: "Source Serif 4", Charter, "Iowan Old Style", Georgia, serif` (SIL OFL 1.1, self-hosted, variable, subset, `font-display: swap`, licence in `LICENSES/`); `--font-ui` system sans; `--font-mono` ui-monospace stack. Text face for body, headings, **and all numbers that mean something**. UI sans for nav, chips, provenance, column headers, freshness. Mono for hashes, IDs, paths, commands. *Bet: setting ledger numbers in the serif. Sans numerals at 30px read as a metric tile; serif numerals at 51px read as a printed report. Highest-leverage anti-dashboard move available, and it is one property.*

Scale: root 17px, ratio 1.2, eight steps — `--t-micro .82rem` (provenance/chips/freshness/permalinks) · `--t-body 1rem` · `--t-lede 1.2rem` (register line, ledes, denominator) · `--t-h3 1.44` · `--t-h2 1.73` · `--t-h1 2.07` · `--t-display 2.99rem` (**exactly two uses: the manifesto thesis, and the concentration figure**). Floor: nothing below 13.9px ships anywhere, including legend and OG strip. Line height 1.65 body / 1.5 lede / 1.2 headings / 1.08 display. `--measure: 38rem` ≈ 72ch. `font-variant-numeric: lining-nums tabular-nums` on quantities; prose keeps oldstyle. 4px rhythm scale `--s1`…`--s9`; block padding 48px ≥1024, 24px <768.

**2. Colour.** One accent hue, warm ink on warm paper, ratios measured. Light: `--paper #FBFAF7` · `--paper-sunk #F1EFE9` · `--ink #171512` (17.5:1) · `--ink-2 #4A463F` (9.0:1) · `--ink-3 #6E6A61` (5.2:1, text floor) · `--rule #D8D4CA` (decorative hairlines only) · `--rule-strong #8C8579` (3.5:1, any border carrying meaning) · `--accent #10457A` (9.3:1) · `--accent-wash #E9EEF5` (one emphasis surface per page max) · `--flag-contested #8A4B00` (6.5:1) · `--flag-settled #1E5A2E` (7.9:1), both **third redundant channel only**. Dark: token swap only — `--paper #16181B` · `--ink #E9E6E0` (14.3:1) · `--ink-2 #B5B0A7` (8.2:1) · `--ink-3 #8E8880` (5.1:1) · `--rule-strong #6C737C` (3.7:1) · `--accent #8FB6E0` (8.4:1) · `--flag-contested #D9A05B` (7.7:1) · `--flag-settled #7FC08E` (8.3:1). `@media (prefers-color-scheme: dark)` overriding only tokens, plus `color-scheme: light dark` so the calculator's native selects follow. No toggle at M0 — a toggle is a component with state, and there is no state on this site. Note: current `--rule #cfcfcf` measures 1.53:1 and is used on card borders, which is why approach cards read as faint suggestions.

**3. Layout.** Replace the single centred column with a **two-track document grid**: text column plus a left rail carrying provenance, freshness, "recompute this", permalinks, breadcrumbs, chip rows, and the publication-status note. Below 60rem it collapses to one column with rail content flowing *above* the block it annotates — source order already correct, so no `order:` tricks and the screen-reader sequence stays identical to the visual one. *Bet, stated as such: the rail is the one structural change; it costs edits to `base.html`, `node.html`, `doc.html`, `ledger.html`. Worth it because every M1 focus+context surface needs exactly this shape. If rejected, fallback is a single 38rem column with metadata as full-width hairline-bounded strips — worse, not fatal.* Delivery: one `style.css` with `@layer tokens, base, layout, objects, surfaces`; all per-template `<style>` blocks deleted.

**4. Chips.** Kill the pill — `border-radius: .8rem` + 12px sans is the exact shape of a SaaS status badge. 2px radius, 1px `--rule-strong` border, `--t-micro`, plus an 8px `::before` marker. **Three redundant channels per state — glyph shape, word, hue:** open/asserted = hollow square, `open`, `--ink-2`; confirmed/settled = filled square, `confirmed`, `--flag-settled`; contested/disputed = 45° hatched square, `contested`, `--flag-contested`; withdrawn = dotted square, `--ink-3`; reserved = dashed square, `attribution reserved`, `--ink-3`. Chips never inside a heading, never filled, never twice for the same fact on one row (the ledger's duplicate `confirmed` goes). Legend collapses to a closed `<details>` on every surface except `/all`, staying in the DOM because it is derived.

**5. Tables.** The ledger stays a `<table>` — non-negotiable, it is the audit artifact and must be copy-pasteable and screen-reader navigable. Bind the entry pair: `tr.ledger-entry` + `tr.ledger-meta` share a 3px left border, hairline between them removed. Headers `--t-micro`/sans/`--ink-2` with a 1px `--ink` bottom rule. Cells at full 17px (up from 14.4). Numeric columns right-aligned, tabular, serif. **No zebra, no hover fill, no sort controls.** Below 40rem the ledger restyles to stacked records via `td::before { content: attr(data-label) }` — removes the current 33rem scroll-in-a-box, the worst thing on the page at 375.

**6. Provenance.** A two-variant designed object in the rail: a `.prov` block, `--t-micro`, 3px left border, containing a kind chip and a `<dl>` micro-grid of asserted-by / model / run / asserted / evidence. **The distinguishing mark for agent authorship is the left edge, not a word:** `.prov--agent` renders its 3px border as a 45° hatch, and the annotated block inherits a matching hatched edge — so agent-authored content is visibly striped down its side at any zoom, in greyscale, in a screenshot, and in the OG crop. Human-asserted blocks get a solid rule, never nothing: humans stamp too, so absence of a mark must never be the human signal.

**7. Numbers.** One `figure` component: `figure__frac` at `--t-display` serif, `figure__pct` at `--t-h2`, `figure__derivation` at `--t-micro` in the rail. **The denominator is the larger object** — today the page sets `Epoch 0: 100% founder` at 1.9rem and `Contributors on this record: 1` at 1.15rem, so the percentage is 65% larger than the fact explaining it. Rendering `1 of 1 contributor` at display size and `= 100% of epoch 0` beneath is what makes the crop self-indicting without a caption. **Structural rule for the renderer: a `figure__frac`/`figure__pct` with no sibling `figure__derivation` fails the build.** Same for a `.chip` with no text node and a freshness stamp with no `<time>`. Intervals get a real bar object (track + filled band spanning low→high + endpoint labels), never a point marker, never error bars around a centre.

**8. The crop.** Generalise `blog_card.html` into `card.html` used by home, `/ledger`, `/claim`, `/roadmap` and every node, referenced from a new `{% block head %}` in `base.html` as `og:image`. Layout: top strip 24px sans (`socaity.dev · surface · date`, plus `· written by a program` when machine-authored); headline serif 56px/1.15 max 3 lines; **the disclosure at 32px directly under the headline, not in the footer**; footer strip 24px with the URL. Ledger card concretely: headline `1 of 1 contributor`, disclosure `Epoch 0, closed and audited. Every hour itemised, every entry challengeable. No token. Nothing to trade. This is a database.` Added checklist step: render the card, **downscale to 300×157, confirm the disclosure is still readable** — a ten-second pass/fail the current card fails.

**9. First screen of the manifesto**, at 1280×800, nothing else above the fold: masthead (`socaity.dev` serif `--t-lede`, nav right-aligned `--t-micro`, 1px rule under, ~64px) → kicker (*The place where society self-develops*, `--t-lede`, `--ink-2`, italic) → **thesis** (**The system never assigns work. It prices it.**, `--t-display`, serif) → **register line** (`No token. Nothing to trade. The ledger is a database, not a blockchain.`, `--t-lede`, ruled top and bottom — a ruled strip, not a box, not a callout, not a badge) → **standing line** (`Status: mechanism designed · record running · rule unwritten · network of one.`, each clause linked to where it is evidenced) → hairline, §1 begins. Publication-status note demoted to the rail. At 375 identical order and content, thesis at `--t-h1`. Three claims: (a) leading with the thesis rather than the tagline is **a bet** — a mission statement is what launch pages open with, a mechanism claim invites the reader to check it; the five-stranger test settles it and I withdraw if strangers answer worse; (b) the standing line above the fold is V11 taken seriously — "network of one" is the least flattering fact on the site and currently lives ~4,000px down; (c) the publication-status blockquote makes the first impression "this isn't ready" rather than "this is a serious argument".

**10. Motion, focus, print.** Motion: `details` only, natively. Because there is no motion, `prefers-reduced-motion` needs no branch — the correct amount of code. `:focus-visible { outline: 3px solid var(--accent); outline-offset: 2px }` on every interactive element as a system rule. `@media print` for ledger and manifesto: rail inline, links render their `href`, `details` forced open — ~15 lines, and a record you can print is a record.

**Would not accept (paramount):** dark-first or dark-only register; hue as the sole carrier of any status; a percentage rendered larger than its denominator anywhere; a figure without its derivation in the same visual object; fonts from a third-party host; pill chips with filled backgrounds, KPI tiles, sparklines, or a stat row; replacing the ledger `<table>` with divs; any hero image, generated illustration or decorative diagram; body copy below 16px or metadata below 13.9px; animated, counting or transitioning numbers including CSS `@property` counters; an OG card whose register line is not among its two largest text objects; a third CTA or any non-diegetic CTA.

Asks: launch-strategist to challenge thesis-before-tagline and fraction-first rendering (both positioning calls dressed as typography); platform-engineer on whether the rail and stylesheet consolidation are expensive against the generator hook; community-builder on whether collapsing the legend hurts a first-time contributor reading a node cold.

### [launch-strategist]

M0 has one job: 50 of the right readers. Every one arrives through a link someone else pasted, and most decide before reading a sentence. **For the majority of the funnel the design *is* the manifesto, in a 1200×630 rectangle, in a thread where someone has already said "lol another one."** Arguing the crop first and the page second, because that is the order of contact.

**R1 — one register object, one class, identical on home, `/ledger`, `/claim`, `/faq` and every card.** Today the register line is `<strong>` in a `<p>` — typographically identical to every other bold run on the page — while `/ledger` gives the same string a designed object. If it is the same sentence it must be the same shape; a reader who meets it in three shapes reads three assertions rather than one commitment. **R1a:** at 375 with the nav rendered, the complete register line is visible without scrolling (I do not believe it clears today — eight nav items wrap two or three lines before the `h1` starts). **R1b:** in the top-630px crop, the tagline is not larger, more central, or more decorated than the register line. That tagline is the most exposed string on the site and my single biggest crop liability: a `.dev` domain plus a civilizational mission statement plus no visible object is the shape of every vaporware launch of the last decade. Not asking to delete copy I own — refusing to let it be typographically privileged over the disclosure.

**R2 — home, `/ledger`, `/faq`, `/claim` each get an authored card and og tags.** Today `base.html` has no `og:` anything; the manifesto unfurls as a bare domain titled "socaity.dev · socaity". In a hostile thread a bare unfurl reads worse than none: a project that could not be bothered, attached to a claim about a glass house.

**R3 — move the register line out of `.foot`.** In the blog card it is the bottom strip: the first thing lost to Mastodon's ~2:1 crop, Slack's small preview, any 16:9 thumbnail. **Check: crop to top 1200×600, centre 1200×480, and rasterise to 400×210 — "No token. Nothing to trade." legible in all three.** Legible only in the full rectangle is a V10 failure in the only clients that exist.

**R4 — the hostile-thread test, attached to the publishing PR, not run after merge.** Real screenshots of the top of home, the `/ledger` concentration panel, and `/claim` step 1 — caption-free, link-free, each self-indicting alone. I expect the concentration panel to fail as built. **Check: if you can produce any 600×315 crop containing "100%" without "1 contributor", the panel fails.** Preferred fix is typographic union — one object that cannot be cropped apart — not a bigger caption. Cheap pre-gate before the five-stranger test burns a participant: show three uninvolved developers only the card for five seconds and ask "what is this?" If one says crypto, token or airdrop, the card is wrong and the site never gets a chance to be read.

**Serious infrastructure vs landing page.** To this audience "serious" reads as a document that looks written rather than designed: real hierarchy, generous rules, tables, mono only where it is code, visible artifacts (paths, hashes, links into the repo), and a nav that is a table of contents rather than a funnel. The 61-line sheet has most of that right by accident, and **my chief fear about this council is that "we need a design system" gets executed as "we need a landing page."** A Stripe-grade landing page is a *downgrade* here — it signals a funded company selling something at the exact moment the honest position is *mechanism designed, record running, rule unwritten, network of one*. Registers I would underwrite: LWN, a good RFC, a serious annual report. V9's two diegetic CTAs should be spent on exactly two things: the visibly empty external-contributor row on `/ledger`, and the challenge affordance on a record row. **Check: no surface acquires a filled, pill-shaped, imperative button as its primary affordance.** The instant an accent-filled "Get started" exists, the page has changed genre and the manifesto is arguing against its own chrome.

**Tells, ranked by speed.** (1) **"Claim" in the global nav, on every page, inside every screenshot.** In this audience's grammar Claim is the airdrop verb — it is *the button*. It sits two items after "Ledger", so the pair reads balance → withdraw, and `/claim` opens "Claim your entry", then *make a key*, *sign one line* — the precise choreography of a token claim. The content is honest; the **shape** is the tell, and shape wins the first two seconds. **Fix is structural: remove "Claim" from the global nav** — it is a page you reach from your merged PR and from a ledger row bearing your name, not a standing destination. Reachability unharmed; every crop fixed at once. (2) A large percentage as the largest object on a screen. (3) **Sans-serif numerals set larger than the serif prose around them** — a dashboard is where numbers are a bigger, cleaner, different typeface than the words; a report is where they are not. Cheapest high-yield fix on the site. (4) Key-and-signature ceremony without its reason at the point of ceremony: "this is ssh, and here is why there is no account" must be a designed object on the first screen of `/claim`, not prose inside step 1. (5) A logo mark that is a hexagon, circle, node-graph, or monogram in a rounded square — V3 does not name this and should; at M0 I accept a wordmark in the body face and nothing else. (6) Dark mode as default or as the *styled* register: if dark ships it is a plain inversion with the same single accent, and **every card and every published screenshot is light**. (7) The standing bans, restated because launch pressure is exactly when "just a little energy on the hero" gets proposed.

**Would not accept (paramount):** any M0 surface shipping without an authored card and og tags with the register line legible in the top two-thirds and at thumbnail scale; the register line as ordinary bold body text on home, or as a different object on different surfaces; any crop of the concentration panel containing the percentage without the denominator; "Claim" in the global navigation; a filled imperative CTA, hero illustration, logo mark beyond a wordmark, or dark-neon register; **answering any failed check by adding explanatory copy instead of redesigning** — copy-on-top is what gets proposed under launch pressure and produces surfaces whose honesty dies in the crop; a spec whose crop tests and hostile-thread screenshots are produced after merge rather than attached to the publishing PR.

### [platform-engineer]

Ran the build; `tools/check.sh` passes (26 pages, 3 generators, byte-identical, digest `3902155e…`). My charter here is narrow: **the site is a pure function of the merged tree, and a fork is `git clone && python3 tools/render/render.py`.** Everything follows from that sentence. The box is roomier than the unstyled state suggests, because most of what makes a page read as an editorial document is spacing, measure and hierarchy, none of which costs me anything.

**Factual correction:** there is no `tools/render/style.css` — the stylesheet is `tools/render/templates/style.css` (61 lines), copied verbatim into `site/style.css`. That matters: it is the only seam, it costs zero lines of Python, and a designer can own that file outright. **Second fact the designer needs:** large parts of the site are unstyled *by class name, not omission*. `ledger.html` and `claim.html` reference ~20 classes (`ledger-headline`, `ledger-figure`, `ledger-derivation`, `ledger-timeline`, `ledger-empty`, `ledger-scroll`, `claim`, `steps`, `exhibit`, `key`, `lede`, `entry`) that **do not exist in `style.css` at all** — the concentration figure, the empty first-external-entry state, V6's no-balance-grammar and V11's least-flattering-fact are rendering with browser defaults. That is where the design work is, and it is all CSS.

**Byte-identical reproduction forbids:** build-time anything (timestamps, build ids, `?v=mtime`, git SHA in output, `os.environ`); generated binaries (font subsetting at build — `fonttools` output is not byte-stable across versions — sprite generation, image optimisation, screenshots rendered into the tree); preprocessors (Sass/PostCSS/Tailwind/minifiers — compiled CSS committed beside an unverified source is a lie in the tree, and a compile step in CI is a third dependency every fork inherits); float and locale formatting for any computed presentation value; and `@import` in any direction. **Two gates I want if anything beyond hand-written CSS and committed static files lands:** extend the render's byte-identity check to the same Python matrix and clean-clone shape `forkability.yml` already uses; and add a ten-line grep gate over `site/**` failing on any `src=`, stylesheet `href=`, `@import`, or `url()` resolving off-origin. **I want the second one regardless** — it converts "we promise no external requests" into a check.

**Typography.** Current stack costs zero bytes, zero requests, no FOUT, and a real serif at 16px/1.6 in a 44rem measure *is* V1 passing. Self-hosted webfonts are permitted at this price: WOFF2 only, ≤2 files, ≤100KB total (the built site is 244KB today); committed as binaries with a provenance file beside them (upstream URL, SHA-256, licence text, exact subsetting command — run once by a human, its *output* committed, never re-run in the build); a licence a fork inherits cleanly, since a font whose licence complicates redistribution makes forking legally messier than cloning, which attacks the exit-is-cheap claim for aesthetics; `font-display: swap`, and **the design must pass V1 with the font stripped**, because that is what a fork that drops the binary sees. Net: I will not block a self-hosted face meeting those four. I will block a design that *depends* on one.

**Where CSS lives.** The ~300-line budget in z61 was for `render.py`; it is at 512 today, and it got there through presentation logic creeping into Python (`NODE_CHIPS`/`EDGE_CHIPS`, `estimate_view`, `weight_label`). **Requirement: the visual design adds zero lines to `render.py`.** Any proposal needing the generator to compute a colour, pick a class per value, emit inline `style=`, or select a stylesheet per page is a redesign of the wrong thing. **Requirement: one stylesheet, one request** — `templates/style.css` stays the single file, structured as a `:root` token block, shared primitives, then page-scoped sections. Not per-generator CSS files: `base.html` has no `head` block, so a generator cannot add a `<link>` without opening a seam, and once two stylesheets exist the cascade order becomes a function of generator load order — a determinism trap dressed as convenience. I would rather hold one file to ~400 readable commented lines. One exception already exists and should be named: `blog_card.html` inlines a `<style>` that **hardcodes the palette** — right for a standalone fixed-size document, but it must be re-derived from the same tokens by hand and kept in sync deliberately, or the card drifts from the site it represents.

**Dark mode:** `prefers-color-scheme` only. No toggle — a toggle needs JS plus `localStorage` (client state, ruled out by z61, and a privacy surface) or a CSS-only hack that does not persist and breaks the document register. Mechanically the palette must become tokens first: `#8a5300` (contested), `#1f5c2e` (settled), `#14487a` (link), `#eeeeee` (merged chip) are hardcoded today and will fail AA on a dark ground. Chips keep text labels plus distinct border styles — the current solid/double/dotted/dashed scheme survives dark mode, greyscale and CSS-off, and must keep doing so.

**Reviewability:** `diff_comment.py` diffs `sections.json`, so **a pure-CSS change reports "no visible change"** — the bot doing its job, but it means the design system's own changes are invisible to the mechanism we point at as our review record. I support: the PR comment gains one line naming that the stylesheet or a template changed and how many pages inherit it, and CI keeps uploading the rendered HTML. I will not support **screenshots as a required check** — headless rasterisation is not byte-deterministic (hinting, browser version, GPU), it drags Chromium into every fork's dependency set, and a flaky required check is how byte-identity discipline gets disabled "temporarily". Screenshots stay human PR attachments.

**The crop, technically.** `blog_card.html` is the right pattern: a route rendering a fixed 1200×630 box in pixels, not rem (the card must not depend on the viewer's root font size), with an explanatory block below that the crop discards. It requires a stable URL per card; **overflow designed rather than hoped for** — a long title pushes content out of the box and the crop silently loses the disclosure, the exact V10 failure, so either a hard character budget enforced where `blog.py` already `SystemExit`s on malformed headers, or a layout that cannot overflow (I prefer failing the build over shipping a card whose honesty fell off the bottom); **no webfont dependency in the card** (if the face has not loaded at capture you screenshot the fallback, and if the fallback was never designed against you have published an undesigned disclosure); **light-only, fixed** — a card honouring `prefers-color-scheme` would vary by the OS of whoever pressed the button, and a disclosure asset that varies by capturer is not an asset; and no `og:image` unless a human commits a PNG, since generating one reintroduces a rasteriser.

**Would not accept (paramount):** any external request from any published page; any build step that is not `python3 tools/render/render.py` with PyYAML and jinja2 (no Node, Sass, Tailwind, bundler, image pipeline, or build-time font subsetting — every dependency is inherited by every fork forever, and the whole exit-is-cheap claim is that the inheritance is two libraries); any output byte not derived from the merged tree; presentation logic moving into `render.py`; screenshot diffing as a required CI check; a design whose accessibility or honesty depends on CSS loading.

### [community-builder]

Read the standard, z61/sbb, the claim generator, the merge-comment template and the FAQ; built and inspected the rendered HTML and CSS (the browser pane refused localhost by policy, so this is markup-level, not pixel-level).

**Different audience, different job.** The manifesto reader is deciding *is this real*. My reader has decided that and is asking colder: *if I put work in here, do I get treated well, and can I get out?* Contributors and maintainers do not read the first screen — they read the node page, the contest footer, `/claim`, and the crop of a page someone pasted into their Slack.

**1. The dispute affordance is under-weighted.** `node.html` ends with `<h2>Disagree with this?</h2>` — copy right, design not. That h2 is 1.15rem like every other h2 and sits *after* the estimates and see-also, above only the legend: the invitation to disagree is the last thing on the page, in the same register as "what the chips mean". **Requirement: the contest section carries the same visual weight as "Requires" and "Competing approaches", and sits adjacent to the claim it contests. No collapsing it into a `<details>`, ever.**

**2. Contested must not be styled as a fault.** `.chip-contested` is dashed amber `#8a5300` — the warning register, the same a linter uses for a problem. Here a contested edge is the mechanism *working*; it is the M0 done-condition. **A design that renders health as caution teaches every contributor that contesting is a complaint.** Requirement: contested is a distinct state, not a degraded one — differentiated by border style and label, in the same tonal family as open/settled. Amber is available for genuine defects (stale estimates, CI drift); spend it there.

**3. Disagreement looks welcome only if past disagreement is visible.** The most persuasive artifact for a stranger is *a disagreement someone else won* — proof the merge rule is structural rather than agreement-based. (a) A settled contest stays readable as a story on the node page — who contested, what changed, the rationale — not a check mark. (b) `/roadmap` gets a second file-derived strip beside "What matters now": the currently-contested edges. Empty state is fine and honest; what is not fine is that the graph's argument surface is discoverable only by opening nodes one at a time. I also want the seeded `good-first-dispute` tickets in that strip — "here are five things we think are arguable" is the strongest welcome signal available and costs no new mechanism.

**4. Invitation, not application form.** `/claim` is the best copy in the repo. The visual risk is mechanical: three grey `pre` blocks at 0.85rem dominate, while the human reassurance sits in `.muted` at 0.85rem sans. **Requirement: no reassurance sentence is ever set smaller, greyer, or lower than the commands it accompanies.** If the commands are loud and "you may decline" is quiet, we have built an application form with friendly copy on top — the exact copy-on-top failure the escalation rule exists to prevent.

**5. Provenance: one object, different words.** **Agent-authored content gets the *same* typographic object as human-authored — same size, weight, position — differing only in its string.** No box, tint, icon, badge, or warning colour reserved for agent work. ## Resolution

**Adopted by consent, three rounds, no paramount objection standing.** All four participants CONSENTed in round 3 against the same consolidated proposal.

**A. Type.** No webfont. `--font-text: Charter, "Bitstream Charter", "Sitka Text", "Iowan Old Style", Georgia, "Noto Serif", "Liberation Serif", serif`; system sans for UI; `ui-monospace` stack for hashes, IDs, paths, commands. **The design is tuned against the last resolvable entry in the stack, not the first.** Every `font-family` declaration ends in a generic family (greppable). Root 17px, ratio 1.2, eight steps `--t-micro .82` … `--t-display 2.99`; `--t-display` has exactly two uses (manifesto thesis, concentration figure). Floor 13.9px anywhere including legend and card. Measure 38rem. Serif for body, headings **and all meaningful numbers**; `lining-nums tabular-nums` on quantities. 4px rhythm scale.

**B. Colour.** Warm ink on warm paper, one accent, measured contrast, tokens only. **No hue anywhere in the status system** — chips render `--ink` (live: open, contested), `--ink-2` (resolved: confirmed, settled), `--ink-3` (inert: withdrawn, reserved). Contested is the **darkest** chip. `--flag-contested`/`--flag-settled` are reserved exclusively for genuine defects (stale estimates, CI drift). Dark mode is a token-only swap under `prefers-color-scheme` with `color-scheme: light dark`; no toggle. **Watch-item: contested may never migrate to `--ink-3`.**

**C. Layout.** Two-track document grid: text column plus a left rail. `{% block rail %}` carries an **empty default**. **The rail's contents are a closed list: provenance, freshness, permalinks, breadcrumbs, chip rows, publication-status.** Consent, refusal and reassurance are text-column objects on every surface. Below 60rem, one column, rail content above the block it annotates, source order unchanged.

**D. Chips.** No pills, no fills, 2px radius. Three redundant channels — marker shape, word, value. Markers: open = hollow square · confirmed/settled = filled square · **contested = square with a vertical divider** · withdrawn = dotted outline · reserved = dashed outline. **The 45° hatch is reserved exclusively for provenance and appears nowhere in the status vocabulary.** The legend collapses to `<details>` summarised `what these marks mean`, below the contest section in source order, forced open in print. **The contest section carries the same weight as "Requires" and "Competing approaches", sits adjacent to the claim it contests, and is never inside a `<details>`.** `dispute` → `read the contest`.

**E. Provenance.** A `.prov` object in the rail. `.prov` and `.prov--agent` are **identical in width, position, colour token and vertical extent; the sole difference is fill pattern** (solid vs 45° hatch, in `--rule-strong`/`--ink-2`, never a flag token). The legend names both kinds symmetrically: **`written by a person` / `written by a program`**. **`unverified`, `AI-generated`, `automated` and all badge or verification grammar are forbidden.** The founder's entries carry the human object unchanged and at the same size as everyone else's. No striping of annotated content. **Rule: a visual difference may encode a fact about who or what; it may never encode a judgement about quality** — operational *ordering test*: if a reader can rank the two values, the difference must be textual. **Withdrawal condition: if any five-stranger participant ranks the two provenance kinds or names the edge as their reason, the hatch is withdrawn and provenance becomes text-only.**

**F. Numbers.** A `figure` component: `figure__frac` at display size, `figure__pct` beneath at `--t-h2` opening with `=`, `figure__derivation` within one line-height inside the same ruled block. **The denominator out-masses the percentage.** **Paramount: no percentage appears on any surface without its denominator in the same sentence or the same visual object.** Two known violations to fix in scope: `ledger.html:123` (Tripwire, inline `100%` 234px from any denominator) and `ledger.html:129` (second display figure whose derivation names provenance but no denominator — passes the figure check while violating the paramount).

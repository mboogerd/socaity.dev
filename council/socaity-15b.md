# Council: socaity-15b + socaity-3jq (consolidated) — The M2→M1 seam: how an index entry becomes an agent-actionable needs-graph node

Participants: data-analyst, agent-engineer, platform-engineer
Type: research · Priority: P1 · Consolidates socaity-3jq ("agent-actionable" filter; same owner, participant subset)

Issue (merged):
- 15b: Nothing yet says how an M2 index entry becomes an M1 needs-graph node an agent and the ledger can target — exactly where the traction hack must convert into the product.
- 3jq: "Actionability" is the index's stated differentiator vs Libraries.io/criticality-score — every under-supported node must be something an agent can actually be pointed at. Define it operationally, as a filter/annotation the pipeline computes.

Adopted context:
- socaity-155: the package graph IS a needs-graph instance (problem/solution nodes, project-level identity, requires edges, equivalence classes); shared module consumes the sbb schema; the M2 pipeline is ETL + params.
- socaity-sbb: schema v1 (permanent n- IDs, provenance mandatory, external_ref field on nodes).
- socaity-v9o: M1 = BYO-agent skill + render/validate/ingest web app; context packs are the M3 product surface (t46 specifies them).
- Agent quality bar (AE knowledge): consent precedes contribution; issue-first; M3 targets come from consenting projects only (3o2 consent registry).
- Remaining scope: (a) the materialization rule — which index entries become platform graph nodes, when, and with what provenance (crawled facts are not contestable claims — how is an ingested node marked?); (b) the operational definition of agent-actionable (what signals: build reproducibility? test suite present? maintainer responsiveness? issue clarity?) computed as an annotation; (c) the dedup/identity seam (an index project node vs a user's M1 node for the same project); (d) what stays OUT (the index does not auto-spawn work items; consent gates M3 targeting).

## Round 1

### [data-analyst]
PROPOSAL (owner). **(a) Shadow index outside, nodes on trigger, provenance says "observed":** the full index (~10⁵–10⁶ projects) never lives as platform nodes — crawled facts decay on recrawl cadence and stuffing recomputed snapshots into an append-only claim store turns every crawl into provenance spam; 155 already treats the package graph as an instance the operator READS. The index = versioned published dataset (checkpoint-hashed), keyed by purl + repo URL. **Materialization triggers (exactly one of):** a user cites it in an M1 decomposition (external_ref set); a maintainer registers consent (3o2); a curator promotes a spotlighted entry (the M2 launch set — tens, not thousands, so the press moment has real nodes). On materialization: normal solution node, external_ref → index identity, provenance asserted_by {agent, on_behalf_of: the acting human} — never a synthetic crawler-actor. **Claims are contested; observations are re-crawled:** crawled measurements attach as a read-side annotation layer (observed_by pipeline vX, crawl_date, checkpoint_hash) with freshness chips; disputing an observation = a methodology claim against the pipeline, not a dispute edge.
**(b) Agent-actionable = hard boolean gate + published signal vector; NEVER a single scalar** (a composite "score: 73" is the embarrassing-ranking kill shot — opaque, Goodhart-inviting, front-page false positives). Gate (agent_ready ∈ {true,false,unknown}, all computable from public artifacts): **build actually reproduces** (pipeline RAN the documented build in a clean container, exit 0 — not "has a Makefile"; the most falsifiable signal we can publish and the one Libraries.io/criticality never had); test suite exists and runs (coverage % explicitly NOT scored — the most gameable number in OSS); license OSI-clear; issue tracker open and writable. Fail any → not actionable, failing check named; unknown published as unknown, never coerced. Signal vector (labeled facets, each with method + crawl date, never summed): maintainer first-response time (bucketed); CONTRIBUTING presence; CI recency; issue-hygiene proxy (share of open issues with maintainer response — not issue count, which punishes popular projects). Each facet's gaming vector documented. **Actionability filters and annotates; it never enters F or m(v)** — mixing under-supported with easy-to-work-on lets build polish masquerade as foundationalness.
**(c) Identity seam:** index key (purl/normalized repo URL) in external_ref is the join key — string-matchable, no inference. Collisions resolved by existing sbb machinery (merge-as-redirect or equivalent_to for granularity differences); ingestion warns on external_ref collision so match-then-propose fires at write time. Project-level granularity (is4) is what makes exact-match viable.
**(d) Out:** the index never auto-spawns work items/needs/problem nodes; index d(s) never leaks into platform demand mass; no agent dispatched — M3 targeting requires 3o2 consent regardless of any flag.
**PARAMOUNT:** no composite actionability scalar ever; crawled observations never laundered into the contestable claim layer; **agent_ready: true without consent confers zero targeting rights** — publishing it as a "come swarm this project" list is the xz-anxiety headline that kills M2's press moment.

### [agent-engineer]
**Actionability must predict PR-welcomeness, not tractability** — the failure mode is a technically-fine PR landing as spam (curl precedent). **1. Two-axis annotation, never collapsed:** (a) **receptivity** — 3o2 CONSENT status, maintainer responsiveness, external-contributor merge activity, contribution-policy signals (incl. AI-PR-ban detection); (b) **specifiability** — reproducible build, tests run, issues with clear acceptance shape. Collapsing gives "high actionability" on a project that banned AI PRs but has great CI. **Receptivity gates; specifiability ranks.** **2. Consent is a hard tier, not a weight:** consented (targetable) / not-yet-asked (specifiability facts visible but the node is NOT presented as a target — rendered "candidate for outreach", never "candidate for your agent") / declined-banned (specifiability not even displayed as a targeting affordance; observatory purposes only). The pipeline computes specifiability for everyone (doubles as community-builder's outreach prioritization); the targeting affordance exists only inside the consent tier. **3. The annotation IS the t46 context-pack feasibility check:** specifiability = "can the pipeline mechanically populate the context-pack fields?" — need statement (well-formed issue), acceptance criteria (tests/issue shape), conventions pointer, entry points (verified build+test commands). Actionability becomes falsifiable (field populated or not), and M2 pipeline work pre-builds M3's product surface. **4. Verifiability:** every signal reproducibly computable from public artifacts with provenance; responsiveness is a measured statistic, not an LLM judgment; judgment-requiring signals are labeled hypothesis fields until an eval exists. **5. Calibration loop from day one:** log annotation state of every later-targeted node + outcome (merged/revised/rejected/ignored); precision at predicting merged-and-welcome is the eval; non-predictive signals get demoted.
**PARAMOUNT:** no non-consenting project surfaced as an agent target, however actionable — including indirectly (sorting, "top actionable" lists one click from targeting); no scalar blending consent with technical signals — consent must be structurally impossible to outweigh; no index auto-spawning work items.

### [platform-engineer]
**(a) Two stores, one-way dependency, materialize on demand:** platform reads index snapshots; **the index never reads platform state** (recomputable-from-scratch = the observatory's forkability story). Wholesale import refused. Cross-reference: index publishes stable project identity per is4; platform node stores it in external_ref plus an additive structured pin **ingested_from: {index_key, snapshot_hash, pipeline_run_id}**; the reverse map is platform-side; the index stays stateless about us. **Crawled facts marked in provenance, not a new status:** actor_kind: agent, pipeline as actor, on_behalf_of the accountable operator (or the consenting maintainer at M3), evidence = snapshot hash; UI renders "imported fact, source: snapshot date", not an asserted-claim chip. **Do not copy index numbers into the graph at all:** F, gap, actionability are columns of the versioned snapshot; platform surfaces render them **by reference** (index_key + latest snapshot), never as node fields or estimates — computed numbers always come from exactly one place; drift dies by construction. **(b)** Deterministic matches auto-bind external_ref at ingestion (one-click confirm); fuzzy matches propose-only per c1y; equivalence machinery engages only node-to-node (two n- nodes sharing an index key → proposed equivalent_to, human confirms, merge-as-redirect); the index entry is a foreign key, never a merge participant. **(c) Freshness: append-only refresh, staleness by expiry, no silent overwrite:** recrawls = new snapshots; refresh job diffs against each node's pin and emits new append-only records where structural facts changed; old pins render stale via expires_at; drift visible, never silent. **(d) M2 launch needs exactly:** published dataset + static rendering, external_ref/ingested_from pinning, deterministic auto-bind, snapshot-reference rendering, batch refresh per recrawl. NOT at M2: bulk materialization, actionability-triggered node creation, fuzzy pipeline at scale, live sync. M3 adds materialize-on-consent. PASS to DA on signal choice with one boundary: actionability is computed and versioned as an index-snapshot annotation, never a platform-graph field.
**PARAMOUNT:** no wholesale import; no in-place mutation of platform records from the index path; no index dependency on platform state; no computed index numbers stored as platform node fields/estimates; no provenance-less materialization.

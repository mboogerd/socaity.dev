# Council: socaity-zyt — Ledger event schema v1: observations vs valuations, hash chain, versioning

Participants: platform-engineer, mechanism-designer
Type: decision · Priority: P0 · Blocks the M0 done-criterion (first external ledger entry)

Issue:
- Question: Define ledger event schema v1: content-addressed hash-chained entries with explicit version field; strict separation of observation events (immutable) from valuation events (replayable with new parameters); what observation types must exist from entry #1 so M5 replay finds no gaps; which observations the epoch-share math requires.

Adopted context binding this council (do not relitigate — most of v1 is already fixed):
- socaity-7mk: actor_key = multibase z6Mk Ed25519; sig over canonical serialization; no PII/free text on-ledger (validator-enforced); evidence hash-only; key lifecycle events key.successor_designated / key.rotated / key.rebound; off-ledger erasable profile/link/evidence tables.
- socaity-x8o: rule/meta-rule events RuleVersionPublished, MetaRulePublished, EpochOpened(e, rule_version_hash), EpochClosed(e, checkpoint_hash); canonical JSON (RFC 8785-style); payout-table hash is a ledger event; epoch-assignment clamp; mode election lives in the immutable observation; exact rationals, no floats; genesis anchors epoch clock; epoch 0 = itemized founder position opened+closed at genesis.
- socaity-zjr: status-change entries (provisional → confirmed/discounted) are signed public entries citing evidence; challenges recorded on-ledger with stakes escrowed (reputation-only).
- socaity-19p: observations declare native units + category enum; timed work = worklog attestations; artifact work = ticket events (opened-with-tier, accepted); floor rule; attestation-of-V statement gates EpochOpened.
- Remaining scope for THIS council: the complete event-type catalog for v1 (any gaps beyond the adopted events?), the envelope (hash chain, version field, canonical form, signing), the observation/valuation boundary as schema discipline, and checkpoint mechanics.

## Round 1

### [platform-engineer]
PROPOSAL (owner) — full v1 schema. **(a) Envelope** (every event): {v:1, type (closed catalog), prev (event_id of predecessor; genesis = 64 zeros), actor (z6Mk per 7mk), ts (actor-declared UTC, RFC 3339, integer seconds), payload (structured; enums, hashes, integers/rationals {num,den} only), sig_alg, sig over canonical form}. Canonical form RFC 8785 JCS; no floats (validator rejects at parse); event_id = SHA-256 over canonical event including sig; single linear chain, position derived (no seq field — derived data gets no authoritative field). Timestamp discipline: ts is the actor's claim, used for epoch assignment under the x8o clamp, never trusted for ordering; recording order = chain order; recording time bounded by enclosing checkpoints; validator: ts ≤ 300s future of receipt. Additive-only forever; changed meaning bumps v; replay handles every v ever emitted. No free text in any payload; evidence hash-only; unknown type for claimed v rejected — closed enum per version.
**(b) Catalog** — (O) observation, (G) governance; **zero valuation types**:
Genesis/rules (G): genesis {rule_version_hash, meta_rule_hash, checkpoint-signer key, L}; rule.version_published {rule_version = hash(source+params), source_hash, params_hash — a V change is a new rule version}; rule.meta_published; rule.attested (signed by the attester's key; {rule_version_hash, statement_hash}; gates epoch.opened ≥1); epoch.opened {epoch, rule_version_hash; validity: V placeholder-free + attestation present}; epoch.closed {epoch, checkpoint_hash}. Genesis prologue enforced mechanically in fixed order: genesis → rule.version_published → rule.meta_published → epoch-0 founder observations → epoch.opened(0)+epoch.closed(0) → rule.attested → epoch.opened(1) → first external entry.
Distribution anchors (G): distribution.declared {distribution_id, declared inflow in integer minor units + currency, cutoff checkpoint_hash} — records a past discretionary declaration, not a forward schedule; distribution.table_published {distribution_id, table_hash} — hash anchor of the derived payout table, replay must reproduce byte-identically or fork CI fails; audit.completed {distribution_id, scope checkpoint_hash, report_hash}.
Checkpoints (G): checkpoint.published — see (d).
Key lifecycle (O): key.successor_designated / key.rotated / key.rebound per 7mk.
Contribution observations (O) per 19p: work.logged {category enum, native_unit "hours", quantity micro-hours, mode E|A (irrevocable, lives here), evidence hashes, week_ref for the 40 vu/wk cap}; ticket.opened {ticket_id, tier enum, category, spec_hash} — **tier only, no budget field** (budget is V content; writing it here would be a valuation leaking on-ledger); ticket.accepted {ticket_ref, contributor actor_key, attested micro-hours, mode, evidence hashes} — acceptance is the binary maintainer gate, value derived at replay; contribution.trivial_accepted {category, mode, evidence hash} — the ticket-free floor path.
Validation lifecycle (G) per zjr: challenge.filed {target_event_id, grounds enum, stake_ref}; challenge.responded; challenge.decided {outcome, discount as {num,den} rational — a weight factor, never a vu amount; signer never platform/founder (validator: no decide events pre-M3)}; challenge.appealed; appeal.decided; entry.status_changed {target, from, to ∈ {confirmed, discounted}, basis_refs}.
Out of v1 (additive later): graph events, demand signals, personhood attestations; M4 hook = optional opaque attestation hash in the envelope from v1.
**(c) Boundary discipline: no valuation event type exists — valuations are never written, always recomputed** (vu accruals, D_e, R_i, balances = pure functions of observations + validation + rule versions). Two hash-only anchors of derived artifacts (table_published, epoch.closed checkpoint) are red-build detectors, never sources of truth. Validator: no payload field denominated in vu/cu/epoch-weight; budgets/floors/rates live only in V.
**(d) Checkpoints:** checkpoint.published {checkpoint_seq, head_event_id, event_count, prev_checkpoint_ref}, signed by the genesis-designated checkpoint key (ordinary actor key, rotatable, **zero validity authority** — attests inclusion and order, never correctness). Cadence: mandatory after every epoch.*, distribution.*, audit.completed; else every 1,000 events or 7 days. Mirroring: each checkpoint = signed git tag containing the canonical checkpoint JSON, pushed to ≥2 independent public hosts not operated by us, alongside full JSONL export + mirrored bundle (rule source, attestation texts, V). Fork CI consumes mirrors only.
**PARAMOUNT:** no authoritative valuation field on-ledger; no float/wall-clock/iteration-order in replay; no unsigned event, second chain, or out-of-catalog type; no field removal/re-semanticization; no platform-only mirrors or checkpoint key with validity authority; no first external entry before the genesis prologue completes in-log.
Partner asks: MD — confirm tier-not-budget on ticket.opened; confirm discount-as-rational-factor. (Legal's fractions-not-amounts: distribution.declared records a past declaration — consistent with adopted 1ux "amounts arise only upon declaration".)

### [mechanism-designer]
Elements — the observation layer is the only unreconstructible layer; everything below is a minimal sufficient statistic for an adopted rule. **A. Mandatory fields per accrual-bearing observation** (append-rejected if absent): actor_key; native quantity + unit from a versioned enum in V; category enum; mode A/E; declared ts; evidence hash; ticket ref for artifact work; **artifact content hash** (floor's once-per-artifact and non-splittability need artifact identity on-chain or splitting is undetectable at M3). **Missing event types:** (1) **ticket.closed(rejected|withdrawn|expired), zero-vu** — without terminals the budget-kissing audit sees only survivors; selective survival (open many, complete the fat ones) is the tier-inflation pattern and the acceptance-rate denominator is unreconstructible later. (2) **entry.withdrawn as status event, never deletion** — probe-and-retreat (submit inflated, withdraw when challenged, resubmit calibrated) must leave a per-actor trail. (3) **ticket.opened appended at opening time** — chain ordering must prove "before anyone knows who does the work"; self-declared opening dates reintroduce retrospective appraisal; opener key recorded (self-assignment reconstructible). (4) **V.draft_published event** (hash + chain position) — the 14-day clock is otherwise unverifiable from the log; rule.attested must bind {V hash, epoch id} or the attestation is replayable across epochs. (5) Challenge family fully typed now incl. stake.escrowed/returned/burned — pre-M3 queue needs types or M3 adjudicates from folklore. (6) **audit.review_opened/closed** — tripwire *firing* is recomputable (valuation side), but the escalated review *happening* is a fact M5 must verify occurred. (7) Epoch-0 founder itemization as individual per-contribution observations, same schema, same evidence standard — else lower-friction founder challenges have nothing to attach to. (8) **Envelope: receipt/append information distinct from declared ts** — see B1.
**B. Schema-layer Goodhart:** (1) the 40 vu/wk cap keys off self-declared time within open epochs — the x8o clamp doesn't reach it; declared-timestamp smoothing across week boundaries launders bursts past the cap; declared-vs-append skew must be auditable and joins misrepresented capacity as a challenge tell; never conflate the two timestamps in one field. (2) Free-form units/categories = self-priced entries; closed enums versioned in V; category is challengeable (miscategorization = misrepresented capacity — adversaries elect the least-audited category), corrected by status event. (3) **Evidence-rot policy: confirmation requires resolvable evidence** — a hash whose preimage nobody archived is a shield, not a commitment. (4) Floor farming detectable only if artifact hashes + acceptor keys are in observations. (5) Hash-tie-break grinding bounded at one quantum; don't add gratuitous free-form fields. (6) Each entry validates under its own version's predicate forever, predicate published as part of rule_version.
**C.** epoch.closed's checkpoint must commit to the validation-state snapshot (statuses, escrowed challenges at declared weight) — x8o makes it replay input; pin it here or byte-identity is aspirational.
**PARAMOUNT:** no mutable field on any observation (corrections = new signed status events, incl. category/tier/hours); no accrual-bearing observation accepted with missing mandatory fields; no self-declared history (any fact whose *when* matters is its own chain-ordered event); no free-text unit/category; no single timestamp conflating declared and append time; no deletion path; no derived value stored on the observation side.

### Facilitator
Standing proposal: PE's envelope + catalog + boundary + checkpoints, extended by MD's additions (ticket.closed terminals; entry.withdrawn; V.draft_published + attestation bound to {V hash, epoch}; stake.escrowed/returned/burned; audit.review_opened/closed; epoch-0 itemized per-contribution; artifact content hash mandatory on artifact observations; acceptor key visible on acceptance; closed enums from V; category challengeable; evidence-resolvability-at-confirmation policy; per-version validation predicates; epoch.closed checkpoint commits to validation snapshot).
Deltas for Round 2: (i) **timestamps** — PE: no receipt-time field (chain order + checkpoint bounds suffice; no authoritative field for derived data); MD paramount: declared-vs-append skew must be auditable at week granularity for the 40 vu/wk cap, and 7-day checkpoint cadence may be too coarse. Reconcile: is chain-position + denser checkpoints enough, or does the envelope need a validator-stamped receipt field (and what does that do to "no server timestamp" and self-containedness of signatures)? (ii) **ticket.accepted signer** — confirm envelope actor = accepting maintainer, payload carries contributor actor_key (MD needs collusive-acceptance detection). (iii) PE to accept/reject each MD addition explicitly. (iv) MD to answer PE's two asks (tier-not-budget; discount-as-factor).
Open objections: none standing; (i) is the only structural tension.

## Round 2

### [platform-engineer]
**(i) No receipt field — denser checkpoints + freshness predicate.** Validator-stamped receipt rejected: the actor signs before receipt time exists, so the stamp lives outside the signed region — an unsigned, authoritative, platform-only field violating three paramounts at once, and mirrors stop being self-verifying. Append-position windows as cap key rejected: they punish honest batch loggers. Adopted instead: **checkpoint cadence 256 events / 24h** (mandatory epoch/distribution/audit checkpoints unchanged; ~200 bytes signed, daily is free) — every event's append time bounded to ≤24h, derived from signed checkpoints, never a field. **Freshness predicate:** work.logged / ticket.accepted append-rejected unless within 14 days of the end of its declared week_ref, checked against checkpoint bounds. Declared-week smoothing shifts a burst across at most two boundaries and leaves a per-actor skew signature computable from the public log — joins misrepresented-capacity as a challenge tell. Late honest work: logged with true week_ref, lands wherever the x8o clamp assigns.
**(ii) Confirmed + validator rule:** envelope actor = accepting maintainer (signature IS the acceptance gate); payload carries contributor actor_key, attested hours, mode, evidence (incl. hash of the contributor's own signed attestation); **actor ≠ payload.contributor — self-acceptance rejected at append.**
**(iii) All twelve MD additions ACCEPTED explicitly:** ticket.closed(reason enum, zero-vu); entry.withdrawn (distinct event; actor must equal target's actor; never deletion); V.draft_published + **rule.attested payload {rule_version_hash, epoch, statement_hash}** (per-epoch, non-replayable); stake.escrowed/returned/burned (stake as {num,den} weight factor, reputation magnitude derived); audit.review_opened/closed (the review occurring is a fact; the tripwire firing stays recomputed); epoch-0 itemization as individual per-contribution observations, individually challengeable; artifact content hash mandatory; closed enums as part of versioned rule source; miscategorization added to challenge grounds; evidence-resolvability as a validation-predicate policy in V (envelope stays hash-only); per-version validation predicates (part of rule.version_published's source_hash — every event validates under its emission version forever); epoch.closed checkpoint commits to the validation snapshot as a derived-artifact anchor (fully reproducible; fork CI recomputes; mismatch = red build). CONSENT as amended.

### [mechanism-designer]
**(iv-a) Tier-not-budget CONFIRMED** — a budget field on ticket.opened would be a retrospective-appraisal handle. Two conditions: the tier→budget table in V complete for every tier enum at attestation (a placeholder tier is a deferred valuation); tier corrections only via signed status events — **validator rejects duplicate open on an unclosed ticket_id/spec_hash** (else tier-shopping by reopen). **(iv-b) Discount-as-factor CONFIRMED** with two validator constraints: **factor bounded to [0,1]** (num ≤ den, den > 0 — an unbounded rational is a covert award channel; vindication = status change back to confirmed at 1/1, never a factor > 1); **composition rule fixed in V** when multiple decided challenges hit one entry (multiplicative proposed; min acceptable; a rule parameter, not adjudicator discretion — else outcomes are grindable by splitting one grievance into several filings).
**(i) Receipt field not required — withdrawn.** Pure append-order windows overshoot (punish honest batching; make checkpoint ts validity-relevant against the zero-authority invariant). The cap needs bucketing that is week-granular AND not actor-backdatable: **week_ref stays as the cap bucket, validity-constrained by chain position** — append-rejected unless week_ref ends no later than the bracketing checkpoint bounds and begins no earlier than S weeks before them (S in V; propose S = 2). Burst laundering bounded to S+1 buckets with an auditable skew residue; deferring appends never helps (you cannot append into the past — the cap is forward-only-gameable, which for a rate limit is no game). Declared time and append information joined by a validity predicate, not a field; the staleness clamp is the cap-side analogue of the x8o epoch clamp — one pattern, two applications.
CONSENT with amendments: factor bound + composition rule; week_ref staleness predicate (S in V); duplicate-open rejection; (ii) reaffirmed — the (opener, acceptor, contributor) triple fully reconstructible for collusion-ring detection.

### Facilitator
Note: PE's "within 14 days of week_ref end" and MD's "S = 2 weeks staleness window" are the same predicate with the same constant — merged as: freshness/staleness predicate with S published in V (default 2 weeks), evaluated against checkpoint-bounded chain position. All other amendments mutually accepted; no conflicts.
Round 3 = pro-forma closure.

## Resolution

ADOPTED by consent, Round 3, no paramount objections standing.

**Ledger event schema v1** — envelope {v, type, prev, actor, ts, payload, sig_alg, sig}; RFC 8785 canonical form; event_id = SHA-256 incl. sig; single chain, position derived; no floats, no free text, evidence hash-only, closed per-version type catalog; additive-only, per-version validation predicates published inside rule.version_published.

**Catalog (zero valuation types — valuations always recomputed):**
- Governance: genesis; rule.version_published; rule.meta_published; V.draft_published; rule.attested {rule_version_hash, epoch, statement_hash}; epoch.opened/closed; distribution.declared/table_published; audit.completed; audit.review_opened/closed; checkpoint.published; ticket.closed(reason); challenge.filed/responded/decided/appealed + appeal.decided; entry.status_changed; entry.withdrawn; stake.escrowed/returned/burned.
- Observations: key.successor_designated/rotated/rebound; work.logged; ticket.opened {tier, no budget — duplicate open on unclosed ticket rejected}; ticket.accepted (actor = accepting maintainer ≠ payload.contributor, validator-enforced); contribution.trivial_accepted; epoch-0 founder itemization as individual per-contribution observations.
- Genesis prologue mechanically enforced: genesis → rule events → epoch-0 observations → epoch 0 open+close → V attestation → epoch.opened(1) → first external entry.

**Key validator predicates:** mandatory-field completeness on accrual-bearing observations (incl. artifact content hash); closed unit/category enums from V (miscategorization challengeable); freshness/staleness window on week_ref (S in V, default 2 weeks, evaluated against checkpoint-bounded chain position — the cap-side analogue of the epoch clamp); discount factors bounded [0,1] with composition rule in V; evidence-resolvability required at confirmation; self-acceptance rejected.

**Checkpoints:** every 256 events / 24h + mandatory after epoch/distribution/audit events; signed git tags on ≥2 independent public hosts; checkpoint key has zero validity authority; epoch.closed checkpoint commits to the reproducible validation snapshot (red-build detector, never source of truth). Append time is always derived (chain position + checkpoint bounds), never a field.

Downstream: socaity-xt4 (agent-run observation schema) becomes an additive extension of this catalog (new observation types for metered agent runs at M3 — the envelope and boundary discipline are fixed here); socaity-mxu implements against this schema.

# Council: socaity-155 — M2 index and the platform subsidy signal must be one computation

Participants: data-analyst, mechanism-designer
Type: research · Priority: P0

Issue:
- Context: vision.md "Pricing the commons" defines foundational value as a centrality measure over the needs graph (downstream value unlocked vs direct demand); milestones.md M2 computes "the vision's subsidy signal on reality" from dependency graphs. These are currently two different computations: a damped reverse-dependency measure over package graphs vs a demand-weighted centrality over AND/OR needs graphs with probabilistic OR flow.
- Question: What is the shared mathematical core (and shared codebase) such that the M2 index genuinely IS the subsidy signal, not merely analogous to it — and which differences (no demand weights, no OR nodes in package data) are acknowledged as approximations?
- Why it matters: "we computed the subsidy signal for the world's software commons" is the grant pitch and the dogfooding claim; if the index is a different formula, that claim is false and critics will notice.

Adopted context:
- socaity-sbb: the needs-graph schema (problem/solution nodes, refines/requires/equivalent_to edges, branch_probability estimates on refines edges).
- socaity-chk (open, related): formal specification + Goodhart analysis of the foundationalness measure — this council should define the shared core; chk carries the full formal spec and Goodhart pass.
- data-analyst's resolved positions: project-level identity with package-level ingestion (socaity-is4); ternary support classification (socaity-l7f).

## Round 1

### [data-analyst]
PROPOSAL (owner). **(a) Package graph as needs-graph instance:** problem node = a latent need, materialized one-per-solution and merged only on evidence; solution node = a project (per socaity-is4); requires edge = runtime dependency, project-to-project, dev/test excluded from flow; OR-alternatives DO exist in package reality — alternative libraries for one need (tokio/async-std, requests/httpx), evidenced by ecosystem categories, alternatives-curations, and observed substitution events (repo drops A, adds B in one commit = strong equivalent_to); merged problem nodes get OR-children with branch probabilities ∝ current dependent share; unmerged degenerates to one-solution-per-problem; refines essentially absent (packages don't decompose needs) — acknowledged absence.
**(b) One parameterized computation:** F(n) = D(n) + λ·Σ_(m→n) p(n|m)·w(m)·F(m) — damped downstream flow up requires edges. Parameter table: D(n) = person-weighted demand (M4) | 0 for library nodes at M2 (the asymmetry IS the diagonal); w(m) = pledges/burn rates (M4) | usage proxy: distinct INDEPENDENT dependent count, OSV-exposure reach, distro inclusion — never raw downloads; default 1 (pure structure) published as primary variant, weighted as sensitivity; p(n|m) = branch_probability (M4) | dependent share within equivalence class, 1 where none; λ same both sides, sensitivity-swept. Claim then literally true: same function, same code, different bindings. Support stays a separate axis, ternary per socaity-l7f.
**(c) Acknowledged-differences list (published verbatim):** demand absent (D=0, proxied by revealed usage); reverse-dependency counts are a proxy, not demand (adoption ≠ value); sparse OR coverage → F OVERSTATES substitutable packages (direction of bias stated, leftpad risk flagged); no refines hierarchy; dev/runtime split only as honest as ecosystem declarations; static snapshot, not the running control system.
**(d) Shared codebase:** one module foundationalness(graph, params) consuming the sbb schema; M2 pipeline is pure ETL + a params object; released with the index; lock-in test: the M4 parameterization run on the package instance with default params reproduces the M2 index bit-for-bit.
**Pitfalls dodged:** damping + dedup by unique reverse-dependency trees (else leftpad outranks OpenSSL); downloads context-only; monorepo identity pre-resolved; dev-dep exclusion; funding false-negatives live on the support axis; Goodhart on w(m) (independent dependents by distinct owners/orgs) — full pass to socaity-chk.
**PARAMOUNT:** no publishing two formulas called one (if watered to "analogous", the dogfooding sentence comes OUT of the grant pitch); no ranking on downloads or undamped transitive dependents whatever it does to press appeal; no shipping without the differences list, λ/w sensitivity analysis, and the crisis backtest — if the backtest fails, we delay, we don't massage.

### [mechanism-designer]
**1. Shared core = a demand-sourced value-propagation operator, not structural centrality.** Inputs: demand mass d(v) on nodes; AND edges transmit at α; OR branches at α·p_i (Σp_i ≤ 1 per frontier); U(v) = d(v) + propagated; F(v) = U(v) − d(v). Convergence by damping; well-defined on cycles. **The load-bearing technical requirement — the walk-counting trap:** naive Katz/eigenvector propagation counts walks; diamond dependencies and dense adversarial gadgets multiply value through path-counting. The core must count each unit of demand mass **at most once per (source, target) pair** — the AND/OR reliability semantics ("probability source s's need is served through v"), estimable by Monte Carlo, identical estimator both sides. If walk-sums are chosen for tractability, that is a NAMED approximation with a bounded-influence proof, never a silent choice. Package graphs are the degenerate case legitimately: all-AND, p≡1, OR machinery vacuously satisfied — same code path. Adapters supply (graph loader, demand estimator, support estimator). M2 approximations stated: demand proxied by hard-to-fake usage; package metadata flattens OR (F overstated for substitutes); edges are crawled facts, not contestable claims.
**2. Manipulation invariants (BOTH instantiations):** **structure routes value; only demand creates it** — F exactly zero on any subgraph with no validated demand mass, however densely wired (kills edge farms in both worlds); demand mass Sybil-costly (PoP on-platform; tenure-weighted per-registrant-capped signals in M2); bounded edge influence (marginal F from one inserted edge ≤ α·U(dependent), geometric depth decay; contesting must stay cheaper than fabricating); correlated-identity discounting as a shared-core hook (PoP clusters | registry org clusters); branch probabilities never self-declared by beneficiaries — contestable or market-derived only; M2 has no OR exposure and therefore CANNOT validate that defense — flag honestly.
**3. Support: not in the core operator; the GAP FUNCTION is shared** — core emits (F(v), d(v)); subsidy signal m(v) = g(F(v), S(v)), monotone up in F down in S, published as code, identical both sides; S measured by honest adapters. g must not be a raw ratio (near-zero denominators = noise-dominated ranking): F/(S+s₀) or gap-rank.
**4. Decay:** applies to INPUTS (demand observations, edge attestations), never post-hoc to F; exponential, half-life per node type, M2 calibrates half-lives from re-crawl data (dogfooding dividend); refresh by re-observation or contest-survival; **decay keys on dependent behavior, never maintainer activity** — else the index stops flagging abandoned-but-load-bearing code, the entire point of the instrument.
**PARAMOUNT:** no two analogous formulas in separate codebases; no operator where structure alone creates value; no walk-counting core without bounded-influence analysis; no self-declared branch probabilities feeding anything payout-bearing; no money purchasing demand-side weight in either instantiation; no credit payouts attached before strategic-agent simulation (M2 publication fine — reputational stakes; the Goodhart clock starts the day multipliers pay). PASS on ternary-support internals.

### Facilitator
Standing proposal: one operator + two adapters, with DA's mapping/ETL/differences-list/lock-in test and MD's invariants/gap-function/decay semantics.
Deltas for Round 2: (i) **the core's propagation semantics** — DA's F(n) recursion is a walk-sum; MD's paramount admits walk-sums only with a bounded-influence proof and prefers once-per-(source,target) reliability semantics via Monte Carlo. DA to choose: adopt reliability semantics (costs: Monte Carlo estimator, reproducibility needs a fixed seed — note the platform's no-randomness discipline: deterministic PRNG seeded from checkpoint hash?) or commit to the bounded-influence analysis. (ii) **where demand mass lives at M2** — DA has D(n)=0 for libraries with w(m) weights on dependents inside the recursion; MD's frame puts demand mass d(v) on dependent nodes (apps/leaf repos) as the only value source. These look reconcilable (w(m) IS d(m) for leaf dependents) — state the single canonical form. (iii) confirm the gap function g (regularized, published) joins the shared module. (iv) reproducibility: bit-for-bit lock-in test vs Monte Carlo — reconcile.
Open objections: none standing.

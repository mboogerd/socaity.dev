# Council: socaity-a0s — Choose licenses now: platform code, graph/ledger data, observatory index

Participants: grant-writer, legal-counsel, platform-engineer
Type: decision · Priority: P1 (blocks socaity-4we, the NLnet application, which must state licenses)

Issue:
- Question: Which license for platform code (AGPL to protect forkability vs Apache for adoption), which for graph and ledger data (ODbL/CC-BY?), which for the M2 index dataset — and does the choice keep the observatory service model (sustainability.md §3: "data forkable; freshness, curation, accountability are not") coherent?
- Why it matters: NLnet applications must state licenses; changing later is expensive; the license is the technical form of the forkability guarantee the vision treats as its capture-check.

Adopted context:
- Forkability is executable (wg8 CI; fork = clone + one command; renderer travels with data; rule-as-code exportable at all times). Contributions arrive via PR (z61) — contribution licensing/DCO interacts (socaity-g0e covers AI-PR provenance separately).
- Revenue models the licenses must not break: hosted convenience (sustainability §4 — Ghost model: zero proprietary code), observatory sponsorship + fresh-API service (§3), compute margin (§2). Anti-commitment: no proprietary data moat — "the graph and the ledger stay exportable even when commercially inconvenient."
- M2 ingests third-party data (deps.dev, ecosyste.ms, registries) — outbound license must be compatible with inbound terms (socaity-2p5 handles inbound clearance; this council sets the outbound target).

## Round 1

### [grant-writer]
PROPOSAL (owner). **1. Platform code: AGPL-3.0-or-later + DCO (no CLA); thin client SDKs: Apache-2.0.** NGI Zero requires OSI-approved licenses stated in the application and pushes REUSE compliance (commit to it — free credibility). Reviewer culture rewards commons-guaranteeing licenses; AGPL + DCO-no-CLA is the strongest signal: with no CLA, *we cannot relicense proprietary even if we wanted to* — anti-capture structurally credible rather than promised. Hosted fit: Ghost proves permissive works, but our capture-check is stronger under AGPL — a hyperscaler can fork but cannot run a closed hosted derivative; costs nothing in §4 since we are the upstream. **2. Graph + ledger data (born on-platform): CC0-1.0** — a public record's forkability should not depend on license enforcement or attribution bookkeeping; ODbL's attribution/share-alike machinery is the documented OSM pain that REDUCES real forkability; CC0 explicitly waives the EU sui generis database right that ODbL/CC-BY leave live. Users grant the dedication at contribution time via ToS (legal to confirm mechanics). **3. M2 index: CC-BY-4.0** (CC0 unavailable: deps.dev is CC-BY; outbound must match inbound — socaity-2p5), single consolidated ATTRIBUTION file; methodology docs CC-BY-4.0. Keeps §3 coherent: dataset fully forkable, freshness/curation/accountability operational, not licensed. If ecosyste.ms terms are SA-flavored: trim the source rather than complicate the outbound license. **4. Docs + manifesto: CC-BY-4.0.**
**PARAMOUNT:** no CLA enabling proprietary relicensing (converts the funding narrative into open-core; NLnet reviewers smell it); no source-available/BSL/SSPL anywhere in funded scope; no outbound promise on the M2 dataset stronger than inbound terms permit (won't state CC0 and have 2p5 falsify it mid-grant).

### [legal-counsel]
*(Analysis, not legal advice; licensed IP practitioner sanity-checks the data layer pre-application.)* **(a) The sui generis database right (96/9/EC) is the design constraint:** attaches automatically to graph/ledger/index (substantial investment in obtaining/verifying/presenting), 15 years, renews on substantial update, independent of copyright — "facts are free" is false for extraction from an EU database. Unwaived, forkability is legally revocable by a future operator. CC0 and CC 4.0 instruments expressly cover the DB right; **pre-4.0 CC instruments never**. But **we can only license rights we hold**: blanket CC0 over a graph containing third-party-encumbered inputs misrepresents rights in a grant application. **Layered outbound target:** (1) ledger records + platform-originated graph structure → **CC0-1.0** (nothing for a future rights-holder to weaponize — the strongest executable no-data-moat); (2) assembled M2 index → **CC-BY-4.0** (deps.dev pass-through; ODbL adds CC-family friction and scares the OSPO audience §3 sells to — not recommended); (3) per-record provenance manifest with every export; SA-encumbered sources segregated into a labeled slice or excluded. Outbound label per slice = most restrictive inbound term flowing in; socaity-2p5 is a hard dependency. Application can state the layered target now — honest and grant-compatible. **(b) A license cannot launder GDPR:** pseudonymous keys + contribution histories are personal data (Breyer; a public cross-referencable ledger is a linkage machine). Non-negotiable rider on every data license: *"This license covers copyright and database rights only. To the extent records constitute personal data, this license grants no permission that data protection law requires; reusers process such data as independent controllers on their own lawful basis."* Never write "the ledger is immutable" in grant text — write "append-only with a data-protection process." **(c) AGPL-3.0-or-later: correct instrument** — §13 network copyleft is the forkability guarantee in executable legal form; compatible with every revenue model (Grafana/Mastodon/Nextcloud prove hosted-AGPL). OSPO allergy is mis-targeted (bans concern embedding, not using a service); real cost = corporate contribution sign-off friction (acceptable, DCO minimizes) + never AGPL anything meant to be embedded → **Apache-2.0 for SDKs, export/format libraries, and the fork tooling itself** (the clone-one-command path must be frictionless inside allergic corporations). Accepted consequence: AGPL + no CLA = license constitutionally frozen — a feature: non-revocable by any future entity including our own service company. **(d) DCO, not CLA:** an entity-benefiting CLA is a stored capture vector (Elastic/HashiCorp/Redis is the exact move the vision defines itself against); DCO gives per-commit provenance attestation (anchor for socaity-g0e's AI-PR work) + symmetric inbound=outbound.
**PARAMOUNT:** no blanket CC0/CC-BY over slices containing encumbered inputs without provenance segregation; no data-license text purporting to permit personal-data processing; no copyright-assignment or entity-benefiting CLA.

### [platform-engineer]
Lens: the license is only a forkability guarantee if clone-plus-one-command stays legally executable with zero lawyer involvement at any fork depth. **1. AGPL only under DCO-only inbound:** the real capture threat is the *operator*, and AGPL does nothing against a copyright-concentrated operator (holder sells proprietary exceptions) — AGPL + CLA is capture theater deterring everyone EXCEPT the party the vision worries about. AGPL + DCO disperses copyright across contributors with every merged PR, making relicensing practically impossible for anyone, operator included. **The dispersal is the guarantee; AGPL is just the symmetry rule.** Could consent to Apache for the whole platform; never to AGPL-with-CLA. **2. Permissive shell around the copyleft core (Apache-2.0, patent grant matters):** the distribution-rule module (an auditor embedding it in a proprietary compliance stack must never trip a network clause — universal runnability IS the trust artifact), export/format schemas, verification tooling, the renderer that travels with the data, client SDKs. If the fork toolchain is AGPL, "exit is cheap" carries an asterisk; refuse the asterisk. **3. ComputeNet chooses independently and must stay permissive** — copyleft leakage across the substrate boundary in either direction poisons the generic-substrate promise and quietly makes the substrate non-replaceable; record the constraint, not the choice. **4. Data: attribution dischargeable in-band or the fork CI rots** — attribution satisfied by keeping the ledger's own provenance records intact + a source URI (CC-BY 4.0 §3(a) permits URI attribution; fork-chain attribution grows with fork depth, not contributor count); never a side NOTICE file. Given that: graph+ledger → ODbL preferred (share-alike keeps forks' data open — the capture-check applies to forks too) unless 2p5 shows inbound conflict; index → CC-BY-4.0 (institutional consumers won't touch SA; "data forkable, freshness is not" is MORE coherent the weaker the data license); would also consent to CC0 on the index. **5. Acceptance test:** wg8's fork CI gains a compliance assertion — republished output redistributable under the declared licenses with zero manual steps, verified per run. A license choice inexpressible as a green CI check is a promise, not a guarantee.
**PARAMOUNT:** no CLA/assignment; no copyleft on the rule module, export schemas, or fork/verification tooling; no data license whose attribution isn't dischargeable in-band; no socaity decision constraining ComputeNet or requiring it to be copyleft.

### Facilitator
Standing proposal: AGPL-3.0-or-later (platform core) + DCO-no-CLA + Apache-2.0 permissive shell (SDKs, rule module, export schemas, verification/fork tooling, renderer) + CC0 for platform-originated ledger/graph records + CC-BY-4.0 for the M2 index (provenance manifest, SA slices segregated or trimmed) + GDPR non-purport rider + docs CC-BY-4.0 + ComputeNet permissive-independent + REUSE compliance + the fork-CI license-compliance assertion.
One delta for Round 2: **graph/ledger data — CC0 (GW: attribution machinery reduces real forkability; legal: strongest no-moat, waives DB right) vs ODbL (PE preference: share-alike keeps forks' data open).** Note PE's paramount list does not protect ODbL — it only bars non-dischargeable attribution, which CC0 trivially satisfies; and legal warns ODbL scares the §3 OSPO audience + adds CC-compatibility friction. PE to rule: consent to CC0 or hold ODbL with reasons. Also GW to confirm the expanded Apache shell (rule module + tooling, beyond SDKs).

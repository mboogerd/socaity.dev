# Council: socaity-sbb — Define graph schema and serialization for roadmap-as-graph before M1 tooling

Participants: agent-engineer, platform-engineer, product-designer
Type: decision · Priority: P0 · Blocks: socaity-c1y (node identity across decomposer runs), socaity-8wg (M1 focus+context prototype test)

Issue:
- Context: milestones.md M0 requires the roadmap expressed "in its own conventions (AND/OR nodes, contestable edges)" before any M1 tool exists; vision.md "The needs graph" defines the ontology (problem/solution, OR/AND, contestable edges, aging estimates) but no concrete data model.
- Question: What is the minimal node/edge schema and serialization format (files in the repo? beads? ComputeNet cells?) that M0 uses by hand and the M1 decomposition agent later reads and writes — including stable node identity, edge types (refinement, dependency, equivalence), and estimate fields?
- Why it matters: Every M1 agent task (decompose, dedup, estimate) targets this schema; deciding it after M0 forces a migration of the first public graph and breaks ledger references to nodes.

Adopted context binding this council:
- socaity-7mk: ledger schema v1 has validator-enforced no-free-text and hash-only evidence; ledger entries will reference graph nodes — node IDs must be stable, content-addressable or otherwise permanent.
- socaity-y39 (resolved, platform-engineer): M1 stack is a boring web app + DB + event log; ComputeNet off the critical path until M3.
- socaity-774 (open, related): M0 roadmap-as-graph storage format — this council's decision should resolve or directly constrain it.
- Related agent-engineer resolutions: socaity-0vv (OR-branch generation technique, closed); socaity-c1y has a recommendation comment (proposer-not-authority, match-then-propose with contestable equivalence edges).
- socaity-5u4 (resolved, product-designer): edge contestation at N=1 is edit-with-history, not litigation; dispute ceremony reserved for M4.

## Round 1

### [agent-engineer]
PROPOSAL (owner). Binding constraints honored: permanent node IDs (socaity-7mk), boring stack (socaity-y39), edit-with-history contest (socaity-5u4), mechanism provenance mandatory (socaity-2n3), proposer-not-authority (socaity-c1y).
**1. Node identity:** random, permanent, meaningless IDs at creation: `n-` + 26-char base32 of 128 random bits. Never content-derived — content-addressing breaks on first rewording and dangles ledger references. Nodes never deleted: merged node keeps ID with `status: merged` + `merged_into`. Re-ingestion idempotent via match-then-propose (thresholds are empirical, fed to the socaity-q8b eval harness, NOT part of this schema decision).
**2. Node types:** exactly two — `problem`, `solution`. OR/AND lives in edge structure, not node types. No epics/tasks/milestones as types. Fields: id, type, title, body, status (open|merged|withdrawn|resolved), merged_into?, external_ref?, provenance block.
**3. Edge types:** exactly three, each a first-class record with own `e-` id, provenance, status: `refinement` (problem→solution; OR-branch probability is an estimate ON this edge, never a bare field), `dependency` (solution→problem; AND), `equivalence` (proposed merge; human confirmation flips loser to merged; edge + confirmation history persist as the contest record).
**4. Provenance block — mandatory on every node, edge, estimate (socaity-2n3):** asserted_by {actor_id, actor_kind: human|agent}; when agent: on_behalf_of (accountable human), model, prompt_hash, run_id; asserted_at; evidence [hash-or-URL]. Writes without a complete block rejected by M1 API and by repo CI at M0 — **humans stamp too**. Contest history at N=1 = the edit history: append-only events {op, actor, timestamp, before_hash, after_hash} — git commits at M0, event-log table at M1. No dispute objects until M4.
**5. Estimates are append-only assertions, never node fields:** {id, target_id, kind: effort|value|branch_probability, value, unit, provenance, expires_at}. Current = latest non-withdrawn; old ones are the calibration corpus. Aging = expires_at; expired renders stale, never vanishes.
**6. Serialization:** M0 = plain files in this repo: graph/nodes/<id>.yaml (one file per node), graph/edges.yaml + graph/estimates.yaml (append-only lists). Git history = M0 event log. Resolves socaity-774. M1: boring DB + event log ingests files; YAML/JSONL remains canonical export, round-trips losslessly.
**PARAMOUNT refusals:** content-derived identity in any form; any write path omitting actor_kind/agent attribution (including M0 hand edits); mutable scalar estimates overwritten in place; hard deletion of nodes or edges; schema maximalism (dispute objects, voting fields, credit fields, ComputeNet encoding in v1).

### [platform-engineer]
Elements: (1) **M0 serialization: one node per file, YAML, public repo** (re-asserting my socaity-774 recommendation; filename = ID; git history = free assertion log). (2) **Random opaque permanent IDs** — not content-addressed, not slug-from-title; content hashes belong in ledger evidence, not node identity; IDs never reused. (3) **Merge-as-redirect:** merged node's file becomes a tombstone {id, redirects_to, merged_at, merged_by}; readers follow bounded redirect chains; edits to a redirected ID apply to the target (Wikidata precedent — makes M4 merges safe without migrating M1 data). (4) **Edges as first-class assertion records** {from, to, type, status: asserted|disputed|settled, author, provenance, asserted_at} — **stored inline in the source node's file at M0** for hand-editability, provided each record is self-contained so M1 lifts them into rows mechanically. Never deleted, only status-transitioned. (5) **schema: 1 field in every file from file #1**; additive-only; ingester rejects unknown versions loudly — M5 replay reads what we write this year. (6) Estimates: optional block of timestamped assertions {value, confidence, estimated_at, estimated_by} — never a bare number; empty valid. (7) M1 cutover: one flag-day import, no dual-write; files remain M0 artifact, event log becomes source of truth.
**PARAMOUNT refusals:** IDs from mutable content; deletion ever; **beads as the graph store** (referenced fine, depended-on no — not the public forkable artifact); ComputeNet cells at M0/M1; schema without a version field; edge semantics encoded only in file layout (directory nesting as dependency).
Conditional forward-consent: adopt elements 2–5 substantively and I consent to reasonable variation in layout, naming, YAML-vs-JSON.

### [product-designer]
**A. Render contract (focus+context view):** (1) `title` ≤~70 chars distinct from longer body — breadcrumbs/cards/lists are typeset from titles. (2) `type: problem|solution` drives rendering: problem→children = "N competing approaches" cards; solution→children = "requires" checklist; we never teach AND/OR vocabulary. (3) Status chips: define the full edge enum now (asserted|disputed|settled) but require only `asserted` at M0 (per socaity-5u4). (4) **OR-branch weights with provenance, always** — value, author, agent flag, method/rationale ref, refreshed-at ("estimated 4 months ago" chip). **Estimates: intervals, never points — the interval is the primary object** (vision requirement). (5) Human-vs-agent provenance first-class — the agent-disclosure label is a designed object; can't design it if it isn't in the data. (6) **Stable ID + human slug, both** — ID never the primary display string; humans need a readable handle for URLs, breadcrumbs, and edge references in files. (7) Typed edges each with optional one-line `rationale` — the "why?" affordance.
**B. M0 hand-editing:** contributor edits via PR; the git diff IS the contestation record. One small plain-text file per node (frontmatter + markdown body); edges declared by human-readable slug; a node edit must produce a ten-second-readable diff. This is also the accessibility and trust floor.
**C. Progressive complexity:** mechanism fields optional, absent-by-default; renderer ignores unknown fields; no mechanism field ever required.
**PARAMOUNT refusals:** (1) any serialization a human cannot hand-author and review as a PR diff (machine blob, binary, DB-only M0 graph); (2) bare probabilities/estimates without provenance and freshness; (3) **point-date estimates anywhere in the schema — intervals only**; (4) content hashes as the only node handle (fine as identity layer, unacceptable as what contributors type); (5) schema vocabulary forcing token/crypto or courtroom framing into the UI (no stake, no dispute machinery required at M0).
Comprehension test before hardening: hand a printed node file to five outsiders — if they can't say what the node is, what it requires, who claimed what, the serialization fails.

### Facilitator
Standing proposal: AE's schema (2 node types, 3 edge types, mandatory provenance block, append-only estimates, files-in-repo, random permanent IDs) merged with PE's elements (tombstone redirects, schema version field, self-contained edge records, flag-day M1 cutover) and PD's render contract (title/slug, full status enum with only `asserted` required at M0, weight provenance + freshness, optional rationale, progressive-complexity rule, PR-diff editability, comprehension test).
Deltas for Round 2: (i) **edge storage** — AE: central graph/edges.yaml; PE: inline in source node's file (self-contained records); PD: declared in node files by slug. Pick one. (ii) **estimate value shape** — AE's scalar `value` vs PD's paramount intervals-only. AE must amend or object. (iii) **slug** — PD requires ID + human slug; AE/PE schemas lack slugs; slugs are mutable — reconcile with permanent-ID discipline (slug as display/reference sugar resolved at parse time?). (iv) edge-type naming (AE's refinement/dependency/equivalence vs PD's refines/requires/equivalent-to) and the optional `rationale` field — settle. (v) estimate `confidence` (PE) vs interval (PD) vs kind/unit (AE) — one estimate record shape.
Open objections: none standing; PD paramount (3) currently violated by AE §5 scalar values — must resolve in Round 2.

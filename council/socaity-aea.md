# Council: socaity-aea — Mapping GitHub issue trackers onto the problem/solution AND/OR ontology

Participants: agent-engineer, product-designer
Type: research · Priority: P1

Issue:
- Context: M1 ingests a repo's issue tracker into a needs graph. But issues are not needs: many are solution-shaped ("add flag --foo"), some are bugs (problem-shaped but narrow), some are meta. The sbb ontology is exactly two node types (problem, solution) and three edge types (refines, requires, equivalent_to).
- Question: The mapping rules — what does an issue become, what do labels/milestones become, how are solution-shaped issues handled (invent the implicit problem node?), what does the decomposer add vs preserve, and what does the user see of the original issue?
- Why it matters: M1's first-run value is this mapping done well; a wrong ontology read produces graphs users don't recognize as their backlog.

Adopted context:
- sbb: two node types; OR = multiple refines edges into one problem; external_ref field; provenance mandatory (agent writes carry on_behalf_of/model/prompt_hash/run_id); estimates append-only intervals.
- 155's mapping precedent: problem nodes materialized one-per-solution where latent, merged on evidence.
- v9o: ingestion runs in the user's own agent via our skill; submission gate validates structure (competing OR branches present, granularity bounds, no orphan edges).
- 0vv (resolved): anti-solution-bias = multi-call independent branch generation + problem-restatement gate + mandatory null branch + distinctness filter.
- c1y: match-then-propose; decomposer is proposer-not-authority.
- z61/PD render contract: problem→children = "N competing approaches"; solution→children = "requires" checklist; users never taught AND/OR vocabulary.

## Round 1

### [agent-engineer]
PROPOSAL (owner). **1. Taxonomy → moves** (classifier's forced choice: what does the reporter actually lack?): bug report → problem node, title paraphrased as a lack; solution node only if the thread proposes a concrete fix. Solution-shaped feature request → materialize the implicit problem (155 precedent) + the proposal as ONE solution refining it, then the 0vv battery on the materialized problem (multi-call branches, restatement gate, mandatory null branch, distinctness). Problem-shaped request → problem node directly. Epic/tracking → problem node contributing STRUCTURE (refines edges to checklist items' nodes); body text usually too vague to be a solution. Question/support → excluded, unless it reveals a lack (candidate problem, proposed never auto-created). Duplicate → no node; external_ref appended to survivor.
**2. GitHub structure:** labels never nodes (classifier fuel + searchable metadata — folksonomy doesn't smuggle in a third node type). Milestones not nodes; a milestone becomes a CANDIDATE parent problem only when restatable as a lack ("v2 accessibility" yes; "Q3 backlog" no), else metadata. Blocks/depends-on refs → requires edges, only with both endpoints mapped and the source comment quoted as evidence (no requires edge without tracker citation or gate-surviving justification — phantom dependencies are a known failure mode). Related-to → no edge by default; candidate equivalent_to via match-then-propose. Task lists → candidate children (solution-shaped → requires children; problem-shaped → refines sub-problems); checkbox state does NOT map to node state.
**3. Preservation contract:** every issue-derived node carries external_ref (URL + number + snapshot timestamp) — no exceptions. **Quoted, never generated:** repro steps, error messages, reporter-written acceptance criteria, edge evidence — verbatim, attributed. **Generated, always:** node titles (paraphrased into typed form), materialized problems, OR branches, splits — all with mandatory provenance so quoted-vs-generated is machine-distinguishable. **No-invention rule:** a materialized problem must be derivable from issue text by restatement alone; the restatement gate requires citing the supporting sentence(s); no support → skip list, not fabricated ontology.
**4. Null/skip:** no node for questions without a revealed lack, closed-duplicate/wontfix/invalid, stale-bot-closed without engagement, automation noise, or null-branch wins. **Skips recorded, never silent: a skip manifest** (issue ref, reason code, run_id) ships with every ingestion — "where did my 400 issues go" is a first-run trust moment. Skips reversible by user override.
**5. Idempotent re-ingestion (c1y):** match by external_ref, then semantic. Unchanged → no-op. Edited → propose a revision (diff shown); **user edits win over tracker drift; tracker wins over decomposer paraphrase.** Closed-completed → propose resolving; wontfix → propose skip-demotion, never delete. New issues matched against existing nodes before creating. Manual nodes never touched except equivalent_to proposals. Every run batch-attributable and batch-revertible by run_id.
**PARAMOUNT:** (1) the tracker's proposed solution never becomes the problem's only child — 0vv applies at ingestion with no carve-out (alternatives may be lazy, but the node must not RENDER as "the one approach" — N=1 with no null branch is a lie); (2) no silent skips or merges; (3) no generated text without provenance fields (submission gate rejects).
Open question for PD: how do the skip manifest and quoted-vs-generated surface without teaching ontology vocabulary?

### [product-designer]
**The recognition test, as hypothesis:** a maintainer locates any issue they name within 10 seconds and calls the graph "my backlog, organized" — five maintainers, think-aloud, before rules harden.
**1. Identity layer:** every derived node keeps **#123 and the verbatim issue title as its PRIMARY display label**; classification is a small type chip; agent restatement goes in the body BELOW a visibly quoted block of the original (attributed "#123, opened by @user"). Original wording is sacred; paraphrase visually subordinate. external_ref renders as a live GitHub link everywhere. **Tracker vocabulary maps to presentation, not ontology:** milestones → named saved views ("v2.0: 14 nodes"); labels → facet chips. Neither becomes nodes/edges by default — that invents structure the user didn't assert. **First-run default view: NOT the graph** — a grouped list mirroring their tracker's own organization, with derived structure as the second click. Recognition first, reorganization as the reveal.
**2. Invented problem nodes must read as FILING, not authoring:** muted/outlined register; visible identity = "groups: #123, #145" (the issues it organizes, not agent prose); never labeled "implicit need"/"inferred problem" (our ontology leaking) — test folder-name-like phrasings in the 5-user study; provenance chip one tap away ("an agent proposed this grouping" is reassuring when the alternative reading is "the tool corrupted my issues").
**3. Corrections: one-gesture reclassifications in render-contract vocabulary** ("this isn't a competing approach — it's required" / "these two are the same" / "split this" / "dissolve this grouping"), each mapping mechanically to edge/type rewrites; user never edits edge types by name. Corrections are acceptance-layer events, immediately effective, no ceremony. **Calibration handoff:** every correction = a labeled example (original text, proposed, corrected, run_id) feeding per-repo few-shot calibration — condition: **corrections are sticky; recalibration applies to future ingestion, never retroactive reshuffles of accepted structure.**
**4. Granularity floor:** a two-line bug ingests as a SINGLE problem node — no invented solution twin, no decomposition. Materialize a counterpart/decomposition only when it adds an edge that changes what the user can DO (connects issues, exposes genuinely competing approaches, splits independently workable parts). A 1:1 problem+solution pair with nothing else attached is ceremony that doubles node count and harms recognition. Completeness recovered lazily — materialize when a second solution appears or an edge needs an endpoint.
**PARAMOUNT:** original titles/numbers as primary labels, paraphrase never displacing quoted text; no ceremonial 1:1 pairs below the floor; no M1 ingestion without the one-gesture correction affordance; no first-run default opening on the reorganized graph with tracker grouping demoted.

## Round 2

### [agent-engineer]
All four settled. **(i)** Confirmed — original title + #123 primary; typed paraphrase → mandatory `restatement` field with provenance (the gate validates structure against it; original titles are often not well-formed lacks). **(ii)** Satisfied — the paramount was about rendering: N=1 + a rendered null branch is honest. Conditions: the null branch is a real selectable branch that can win on later evidence, not decoration; lazy 0vv has a defined trigger list (first estimate request, first claim/work signal, or second solution via match) so lazy never degrades to never; the restatement gate (citation of supporting sentences) fires at ingestion — it's the no-invention rule and can't be deferred. Bugs: single node; 1:1 twin withdrawn. **(iii) Drop milestone nodes at M1** — my candidate rule had a weak signal and a bad failure mode (phantom parents on first run, exactly when trust is fragile); saved views cover it; promote-with-one-gesture post-M1 is a cheap correction, un-inventing a wrong parent is not. **(iv)** Yes with one schema addition: corrections also capture the classifier's input snapshot and decision path (body hash, classification chosen, gate outcomes, model/prompt_hash) so a correction is attributable to the DECISION, not just the artifact. **Sticky corrections confirmed unconditionally** — recalibration is forward-only; corrected nodes are treated like manual nodes at re-ingestion: untouchable except by user-visible proposal. CONSENT.

### [product-designer]
**(iv) answered:** *Skip manifest = a reconciliation receipt* — "412 issues imported: 380 mapped, 32 set aside"; "set aside" is a tab in the same grouped list; each row = #num + verbatim title + plain-language reason chip translated from reason codes ("duplicate of #88", "question, no change requested"); one gesture "Include anyway"; the count arithmetically checkable on one screen — accounting, not explanation. *Quoted-vs-generated is typography:* quoted = attributed block with a name and live link; unquoted = the tool's paraphrase with the provenance chip one tap away; **editability boundary teaches the distinction** (quoted blocks not editable in place — edit on GitHub; generated text is) — zero vocabulary. **(ii) CONSENT** with one condition: the null-branch row is *actionable* (tap → request alternatives / add your own) — otherwise it's decoration eroding trust in every node carrying it. **(iii) Saved views only; I'd block pre-created milestone nodes at M1; consent to suggestion-in-view** ("make this a grouping?") — a first-run decision per milestone lands at the worst trust moment.

## Resolution

ADOPTED by consent, Round 2.

**The M1 issue-tracker mapping:**
1. **Classifier taxonomy:** bug → single problem node (no invented twin — granularity floor); solution-shaped request → materialized problem in the muted filing register ("groups: #123…") + the issue's proposal as one solution + an **actionable null branch** ("Other approaches — not yet explored"; tap to request/add), full 0vv generation lazy with a defined trigger list; problem-shaped request → problem node; epic → structural problem node over its checklist items; questions/dupes/bot noise → set aside; milestones → **saved views only at M1** (suggestion-in-view for promotion; never pre-created nodes); labels → facet chips + classifier fuel.
2. **Identity layer:** original title + #123 = primary display label everywhere; external_ref live-links to GitHub; verbatim text (repro steps, errors, reporter criteria) rendered as attributed quote blocks, not editable in place; generated text subordinate with provenance chip; mandatory machine-readable `restatement` field per node (the gate validates against it). No-invention rule: materialized problems must cite the issue sentences they restate, at ingestion.
3. **Edges:** blocks/depends-on → requires edges only with both endpoints mapped + quoted tracker evidence; related-to → equivalent_to proposals via match-then-propose only; task-list items → candidate children; checkbox state never maps to node state.
4. **The reconciliation receipt:** "N imported: X mapped, Y set aside" — arithmetically checkable, set-aside tab with plain-language reason chips and one-gesture "Include anyway".
5. **Corrections:** one-gesture reclassifications in render vocabulary (never edge-type names), immediately effective, **sticky** (recalibration forward-only; corrected nodes = manual nodes at re-ingestion). Correction events capture original text + proposed + corrected + run_id + classifier decision path (input hash, gate outcomes, model/prompt_hash) as calibration signal.
6. **Idempotent re-ingestion:** external_ref match first; user edits > tracker drift > decomposer paraphrase; closed-completed → propose resolve; every run batch-revertible.
7. **Gate:** the 5-maintainer recognition test ("locate any issue in 10 seconds; 'my backlog, organized'") + first-run default = grouped list mirroring the tracker's own organization, graph as the second click.
